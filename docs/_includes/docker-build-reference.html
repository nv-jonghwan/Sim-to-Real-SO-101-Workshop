Reference: docker build

Build the workshop Docker image

so101-workshop:latest is built locally from this repository. A Docker Hub login does not create this image. If it is missing, docker run can attempt a Hub pull and report pull access denied.

Run the following steps in a Host terminal before starting the workshop Container. If your checkout uses another folder, use that folder instead of the example path.

  1. Open the repository root and check that its Dockerfile exists.

    cd ~/Sim-to-Real-SO-101-Workshop
test -f docker/Dockerfile

  2. Check Docker access and Buildx. Docker version must show both Client and Server; resolve permission or daemon errors before building.

    docker version
docker buildx version

  3. If Buildx is installed at the Ubuntu path below but docker buildx is not recognized, register it in your user plugin directory. Skip the link command if that link already exists. If the binary is missing, install the Docker Buildx plugin using the official Docker installation guide.

    test -x /usr/libexec/docker/cli-plugins/docker-buildx
mkdir -p ~/.docker/cli-plugins
ln -s /usr/libexec/docker/cli-plugins/docker-buildx ~/.docker/cli-plugins/docker-buildx
docker buildx version

    This link is saved on disk and remains after reboot. It does not restart Docker or interrupt a running build.

  4. Build the image. Wait for the command to finish successfully before starting the Container; the first build downloads and installs the course dependencies.

    docker build --progress=plain -t so101-workshop:latest -f docker/Dockerfile .

    If the Docker CLI still cannot dispatch to Buildx, use the installed binary directly.

    /usr/libexec/docker/cli-plugins/docker-buildx build --load --progress=plain -t so101-workshop:latest -f docker/Dockerfile .

  5. Check the built image and create the persistent data directories.

    docker image inspect so101-workshop:latest --format '{{.Os}}/{{.Architecture}}'
mkdir -p outputs datasets models

    The image architecture must match the Host: linux/amd64 on an x86_64 PC, or linux/arm64 on Spark. Architecture alone does not verify simulation, rendering or policy inference.

  6. Close this reference and continue with the Container start command in the lesson. The built image survives reboot; start the Container again after reboot. Rebuild when the Dockerfile or required dependencies change.
