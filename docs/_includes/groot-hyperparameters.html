Training: many examples, one weight update

Each sampled example pairs images, an instruction, and robot state with a future action window. The loss guides updates to the trainable weights.

  1. Sample windows32 windows / updateImages + instruction + state
  2. Prepare targets16 future action stepsImage augmentation is optional
  3. Compute lossGR00T flow matchingLearn from noisy action targets
  4. Update weightsOptimizer + learning rateRepeat for 20,000 updates

Next update: sample another batch → repeat the loop.

32 windows per update = 32 × 1 GPU process

640,000 sampled windows over the run = 32 × 20,000 updates

Windows can overlap and repeat. This is not a count of unique demonstrations or a prediction of training time. More GPUs at the same batch setting change data exposure, not just speed.

Inference: observe, predict, execute, observe again

Assume the robot executes one action every 33 ms (30 Hz). Use fewer actions from each prediction, and it needs a new prediction more often. The control rate stays the same.

  1. ObserveTwo cameras + joint stateKeep the task instruction
  2. Predict a chunkTrained window: 16 stepsFrozen weights + saved processors
  3. Execute actionsExecute 16 actionsControl rate: 30 Hz
  4. Observe againRefill with a new predictionAfter the selected actions finish
