CODEX#

Use Codex throughout the workshop to prepare the environment, understand the course, follow an exercise, and discuss observations. Instructors, TAs and students use the same repository and the same skill files under skills/.

Ask in Korean and keep technical names such as Physical AI, GR00T, Co-Training and HG-DAgger in English. A course question can be answered from the documents; physical exercises follow the instructor’s sequence and the readiness of your station.

Choose your starting point#

Open the shared workshop folder and ask naturally. AGENTS.md routes the request to the relevant skills/<name>/SKILL.md file. Everyone uses the same files.

Option A: ChatGPT app#

Codex in the desktop app#

  1. Sign in to the prepared ChatGPT desktop app and select Codex in the product selector.

  2. Open a local project for ~/Sim-to-Real-SO-101-Workshop. In an existing project, use Edit project → Add folder; make this repository the primary folder with Make primary. New chats use it to find the course files and skills.

  3. For this workshop, choose Work in → This computer / Local and use the prepared checkout on branch aidayseoul2026. This keeps the chat aligned with the folder mounted in the workshop Container.

  4. Start a chat in this project and ask the connection-check question below, followed by your setup or lesson request. The repository instructions read the canonical skill files directly.

Folder selection is described in Projects and chats; execution choices are described in Codex environments. A cloud environment needs its own files and tools; it does not automatically receive the laptop’s USB devices, running Container or GPU.

Check the current working directory and Git branch. Confirm that you can read AGENTS.md, skills/so101-dli/SKILL.md, and docs/seoul-workshop-schedule.md, and use the relevant skills for subsequent course questions and exercise requests. For now, only verify file access.

ChatGPT Work in the app#

If you prefer the ChatGPT interface, select ChatGPT → Work and use a project that can access the local workshop folder. Availability depends on the account and workspace. Start with the same connection check. See Use ChatGPT.

After confirming file access, ask naturally or name the canonical skill file directly. This workflow does not require a role-specific skill installation or a skill-selector entry.

For ordinary web/mobile Chat without local folder access, attach the relevant lesson and ask questions about it. A GitHub link alone does not install these repository skills or connect the classroom robot. This course distributes local skill folders; it has no separately published ChatGPT plugin.

Option B: Codex CLI#

Use the prepared CLI, or follow the official Codex CLI guide if installation is needed. In a Host terminal, enter the workshop folder and start Codex.

cd ~/Sim-to-Real-SO-101-Workshop
git branch --show-current
codex --version
codex

Confirm branch aidayseoul2026 and complete sign-in if prompted. Enter a natural-language request or ask Codex to read skills/so101-dli/SKILL.md first.

Set up the course skills#

All course skills live in skills/. AGENTS.md tells the agent which canonical file to read for a setup request or lesson question. Keep the folder structure intact so relative lesson references work. No symlinks, personal-folder copies or role-specific activation are needed.

The skill-selector UI may not list these plain folders. Use the connection-check prompt to verify access to AGENTS.md and the requested SKILL.md; direct file reading is the course workflow.

If files cannot be read, check the selected project folder and local file access. A skill request does not itself grant additional permissions or establish robot readiness.

Environment setup#

Ask “Set up the environment” in the shared workshop project. The agent reads AGENTS.md and skills/so101-dli-prepare/SKILL.md, checks the existing installation, and follows the preparation guide. The same skill files support installation, course questions, and exercises.

To check this computer first, ask “Check whether this computer meets the requirements to run the DLI workshop.” The preparation skill reports basic Host eligibility, missing tools and assets, and unverified capacity or runtime checks. A read-only report does not certify classroom execution or start installation, downloads, or robot motion.

python3 skills/so101-dli-prepare/scripts/preflight.py --format markdown

A read-only plan shows the installation checkpoints and commands without executing them:

python3 skills/so101-dli-prepare/scripts/setup_plan.py

Record the agreed source commit, actual model/dataset paths, commands, logs and next action under runs/setup/<station>/. Reuse verified installations and downloads when resuming. Permission errors and untested runtime checks remain unknown.

Build and open the course guide#

Run these commands on the Host from the repository root after preparing the locked documentation dependencies and Git LFS media. Documentation does not require the robot Container or GPU.

uv sync --frozen
bash skills/so101-dli-docs/scripts/build.sh
python3 skills/so101-dli-docs/scripts/verify_html.py

The build prepares both languages. When you build and browse on the same Laptop, start a local preview on an available port:

python3 skills/so101-dli-docs/scripts/preview.py start --bind 127.0.0.1 --port 8095
python3 skills/so101-dli-docs/scripts/preview.py status

After the preview starts, open the course guide or DLI preparation and delivery in that Laptop’s browser. The local service uses http://localhost:8095; building alone does not start the server or open the browser. If you choose a different port, update the links accordingly.

localhost refers to the computer running your browser. For access from another PC, replace 127.0.0.1 in the start command with the server’s verified LAN IP and open the URL reported by the preview on that PC.

Use the verified URL reported by the preview. Keep the requested preview running; its PID, command and log are recorded locally. Use preview.py stop to stop that owned preview. This is background execution, not boot autostart.

Software preparation and robot operation are separate checks. Confirm the current operator and station readiness before powered robot exercises; a model cache or connection message does not establish successful motion.

Try course questions and hands-on requests#

These examples need no skill names. The agent uses the relevant available course skill and lesson. You can ask which skill and source section it used.

Explain how the Sim-to-Real Gap relates to Domain Randomization for today's task.
Read the GR00T guide and explain VLA inputs and action chunks.
Let's work through calibration one step at a time, starting with the current connections.
How does a State Machine dataset differ from a teleoperation dataset?
Under what conditions should we compare sim-only and Co-Training models?

What should I compare between the original and augmented videos?
