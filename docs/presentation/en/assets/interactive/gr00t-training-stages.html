Stage 2 · Post-training configuration

Frozen components still compute features, but the optimizer does not update their parameters. The base workshop example keeps vision and language frozen while training the action components. This drawing groups components conceptually; the saved configuration records the precise trainable set.

Example

Use the adapted policy with fixed weights

Stage 3 · New observations, no optimizer updates

Inference takes fresh images, instruction text, and robot state and predicts actions using the saved checkpoint and processors. Feedback changes the next observation, not the checkpoint weights.

Example

A rollout can observe a different vial position after moving the arm. It makes another prediction; it does not fine-tune itself on that trial. Compare checkpoints under the same covered starting conditions.

Use loss to guide weight updates

Training loop · Loss, optimizer, learning rate

The training objective supplies a loss from sampled predictions and targets. The optimizer updates trainable parameters; the learning-rate schedule controls the scale of those updates. Falling loss alone does not measure successful grasping or placement.

Example

With 20,000 training steps, the optimizer performs 20,000 updates. Assess saved checkpoints with autonomous rollouts as well as training curves.

Optionally adapt visual features

Controlled experiment · Vision trainable, language frozen

Unfreezing permits the vision encoder to adapt to task images. It adds trainable parameters and memory use, and can increase overfitting risk. Keep the other training and evaluation choices fixed when testing its effect.

Example

Compare frozen and trainable vision using the same dataset, batch size, action window, update budget, and rollout conditions. The supplied alternative command also changes batch size and window, so it is not itself a one-factor comparison.
