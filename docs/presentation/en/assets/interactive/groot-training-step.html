How much data goes into one update?

One GPU: 32 windows × 16 action targets = 512 target timesteps per optimizer update.

Illustrative counts, including repeated samples—not unique episodes. Only valid, unmasked targets contribute to the loss. These controls do not change the workshop recipe. Effective batch = batch size per GPU × GPU processes.

Batch size

Batch size counts sampled observation/action windows, not whole episodes. Each window contains camera images, the instruction, joint state, and an action target chunk starting at the sampled frame. In the pinned lesson training loop, batch size × GPU processes gives the effective batch for one optimizer update. Each GPU processes its own batch, gradients are synchronized, and the optimizer updates once. This loop does not accumulate several batches before updating.

Training horizon

The training action horizon is the number of action targets paired with an observation. The targets start at that frame: indices 0 through H−1. Sixteen commands at 30 Hz represent about 0.53 seconds of control; their first-to-last timestamps span 0.50 seconds. Longer chunks change the temporal learning problem and increase target size. The loader caps the requested chunk at the base model’s supported horizon. Use a supported training horizon; it is distinct from how many actions a rollout executes. Arm targets are relative to the observation state; the gripper remains absolute. Image augmentation is optional.

Trainable components

Images, instruction, and joint state condition the model. Flow matching mixes the action targets with random noise at a sampled flow time. The action head predicts the target flow (action minus noise); a masked mean-squared error supplies the training loss. Backpropagation computes gradients for trainable weights. Frozen components still provide features, but receive no optimizer updates. Unfreezing vision adds trainable weights and usually increases memory use.

Learning rate

After backpropagation, the loop clips the gradient norm when configured, then the optimizer updates trainable weights. Learning rate scales this update together with the optimizer. A schedule changes the learning rate across updates. The loop then clears the gradients and advances the learning-rate schedule. This optimizer update counts as one training step. Repeat for the configured number of steps, then evaluate the saved policy.
