Quick Reference#

전체 workflow를 하나의 so101-workshop container terminal에서 진행합니다. 각 실습을 마치거나 종료한 뒤 다음 명령을 실행하세요. Host라고 표시되지 않았다면 container 내부 명령입니다. Build 요구사항과 mount는 Get the Code를 확인하세요.

Build와 시작 — Host#

Host terminal에서 home directory의 workshop folder로 이동한 뒤 container를 build하거나 시작합니다.

cd ~/Sim-to-Real-SO-101-Workshop
docker build -t so101-workshop -f docker/Dockerfile .
mkdir -p outputs datasets models
xhost +
docker run --name so101-workshop -it --rm --privileged --runtime=nvidia --network=host -e DISPLAY -v /tmp/.X11-unix:/tmp/.X11-unix -v ~/.Xauthority:/root/.Xauthority -v /dev:/dev -v /run/udev:/run/udev:ro -v ~/.cache/huggingface:/root/.cache/huggingface -v ~/.cache/ovrtx:/root/.cache/ovrtx -v ~/.cache/warp:/root/.cache/warp -v ./docker/env:/root/env -v ./source:/workspace/Sim-to-Real-SO-101-Workshop/source -v ./outputs:/workspace/Sim-to-Real-SO-101-Workshop/outputs -v ./datasets:/workspace/Sim-to-Real-SO-101-Workshop/datasets -v ./models:/workspace/Sim-to-Real-SO-101-Workshop/models so101-workshop:latest

이후 명령을 위해 container prompt를 열어 두세요. 추가 shell은 선택 사항이며 재접속은 container shell recovery를 참고하세요.

실행 중인 Container에 연결 — Host#

Container가 실행 중이면 host terminal에서 shell을 엽니다.

docker exec -it so101-workshop bash

필요하면 실행 중인 container 목록의 NAMES에서 so101-workshop을 확인합니다.

docker ps

Hardware 확인과 Calibration#

lerobot-find-port
lerobot-find-cameras opencv

outputs/captured_images의 camera preview를 확인하고 아래 예시 값을 본인 station 값으로 바꾸세요.

setenv ROBOT_PORT=/dev/ttyACM0
setenv TELEOP_PORT=/dev/ttyACM1
setenv ROBOT_ID=orange_robot
setenv TELEOP_ID=orange_teleop
setenv CAMERA_GRIPPER=2
setenv CAMERA_EXTERNAL=0

setenv는 mount된 docker/env에 설정을 유지하며 새 container shell이 자동으로 읽습니다.

lerobot-calibrate --teleop.type=so101_leader --teleop.port="$TELEOP_PORT" --teleop.id="$TELEOP_ID"
lerobot-calibrate --robot.type=so101_follower --robot.port="$ROBOT_PORT" --robot.id="$ROBOT_ID"
python docker/scripts/so101_check_calibration.py
lerobot-teleoperate --robot.type=so101_follower --robot.port="$ROBOT_PORT" --robot.id="$ROBOT_ID" --teleop.type=so101_leader --teleop.port="$TELEOP_PORT" --teleop.id="$TELEOP_ID"

Calibration과 Camera Setup을 확인하세요.

두 arm 모두 range sweep에서 wrist roll을 생략합니다. LeRobot이 range를 자동 지정하지만 초기 calibration pose는 맞춰야 합니다.

Follower 수동 제어#

먼저 다른 robot-control process를 종료합니다. 일반 control은 초기 pose로 이동하고 종료 시 home으로 복귀합니다.

python /workspace/Sim-to-Real-SO-101-Workshop/docker/scripts/so101_control.py --robot.type=so101_follower --robot.port="$ROBOT_PORT" --robot.id="$ROBOT_ID"

Torque를 끄고 손으로 움직이려면 --passive_mode=true, telemetry는 --rerun=true를 추가합니다. Joint별 제어:

python /workspace/Sim-to-Real-SO-101-Workshop/docker/scripts/so101_manual_control.py --robot.type=so101_follower --robot.port="$ROBOT_PORT" --robot.id="$ROBOT_ID"

Up/Down으로 joint 선택, Left/Right로 이동, Z로 zero 명령, Q/Escape로 종료합니다.

Simulation과 Recording#

Physics-only 검사:

zero_agent --task Newton-So101-Teleop-Vials-To-Rack-v0 --cameras none presets=newton --visualizer newton

두 camera를 사용하는 teleoperation:

lerobot_agent --task Newton-So101-Teleop-Vials-To-Rack-DR-v0 --cameras all --browser-display presets=newton,ovrtx_renderer

Recording(Local 수집은 username placeholder 유지, upload 시 본인 username 사용):

export HF_USER=your_hf_username
lerobot_agent --task Newton-So101-Teleop-Vials-To-Rack-DR-v0 --cameras all --browser-display presets=newton,ovrtx_renderer --repo_id "${HF_USER}/so101_teleop_vials_newton" --task_name "Pick up the vial and place it in the rack"

http://localhost:8090에 focus를 두고 Space로 시작/저장, C로 폐기, R로 폐기 후 reset합니다. 저장이 끝난 뒤 종료하세요. 같은 dataset에 추가하려면 --resume을 사용하고 viewer에는 tab 하나만 연결합니다.

lerobot-dataset-viz --repo-id "${HF_USER}/so101_teleop_vials_newton" --root "./datasets/${HF_USER}/so101_teleop_vials_newton" --episode-index 0
hf auth login
export DATASET_ID="${HF_USER}/so101_teleop_vials_newton"
hf upload "$DATASET_ID" "./datasets/$DATASET_ID" . --repo-type dataset
hf repos tag create "$DATASET_ID" v3.0 --repo-type dataset --revision main

같은 dataset에 나중에 다시 upload할 때는 tag를 갱신하세요.

자동 Simulation 수집#

다른 simulation client를 종료한 뒤 시작하세요. Recording 없이 preview:

vials_state_machine --task Newton-So101-Auto-Vials-State-Machine-v0 --cameras all --browser-display presets=newton,ovrtx_renderer --visualizer newton

Ctrl+C로 preview를 끝내고 Domain Randomization으로 성공 episode 100개를 수집합니다. Upload하지 않는다면 username placeholder를 유지합니다.

export HF_USER=your_hf_username
vials_state_machine --task Newton-So101-Auto-Vials-State-Machine-DR-v0 --record --num_episodes 100 --repo_id "${HF_USER}/so101_auto_vials_newton" --task_name "Pick up the vial and place it in the rack" --cameras all --browser-display presets=newton,ovrtx_renderer --visualizer newton

목표 달성과 최종 export를 기다리세요. Recorder는 episode를 임시 저장한 뒤 dataset을 조립합니다. 이후 검토하고 upload합니다.

lerobot-dataset-viz --repo-id "${HF_USER}/so101_auto_vials_newton" --root "./datasets/${HF_USER}/so101_auto_vials_newton" --episode-index 0
hf auth login
export DATASET_ID="${HF_USER}/so101_auto_vials_newton"
hf upload "$DATASET_ID" "./datasets/$DATASET_ID" . --repo-type dataset
hf repos tag create "$DATASET_ID" v3.0 --repo-type dataset --revision main

전체 순서는 Automated Data Collection을 확인하세요.

GR00T 1.7 학습과 평가#

전체 학습 명령에 --policy.type=groot와 --policy.base_model_path=nvidia/GR00T-N1.7-3B를 사용합니다.

Teleoperation은 DATASET_NAME=so101_teleop_vials_newton, 자동 수집은 DATASET_NAME=so101_auto_vials_newton을 설정한 뒤 model/output 변수를 정의합니다. 20,000 step을 학습하고 5,000 step마다 outputs/train/<user>/<model> 아래에 저장합니다. Machine에 맞는 single-GPU 또는 multi-GPU 명령을 선택하세요.

Simulation 평가용 policy server를 같은 container terminal의 background에서 한 번 시작합니다.

mkdir -p outputs
python -m lerobot.async_inference.policy_server --host=0.0.0.0 --port=8080 --fps=30 --inference_latency=0 > outputs/policy-server.log 2>&1 & POLICY_SERVER_PID=$!
python -c "import grpc; grpc.channel_ready_future(grpc.insecure_channel('localhost:8080')).result(timeout=60); print('Policy server ready')"

Policy server ready 후 같은 prompt에서 과정의 sim-only policy 또는 본인 checkpoint를 선택합니다.

export MODEL_ID=sreetz-nv/so101_newton_dr500_vision_h32_b32_20k_20260929
lerobot_eval --task Newton-So101-Teleop-Vials-To-Rack-DR-Eval-v0 --cameras all --browser-display presets=newton,ovrtx_renderer --server_address localhost:8080 --pretrained_name_or_path "$MODEL_ID" --policy_type groot --policy_device cuda --start_pose_dataset sreetz-nv/so101_newton_dr500_20260923 --action_horizon 16 --num_episodes 10 --lang_instruction "Pick up the vial and place it in the rack" --seed 76000

자동 수집 예시는 your_hf_username/so101_auto_vials_newton_GR00T17, local checkpoint는 pretrained_model directory의 절대 경로로 MODEL_ID를 설정합니다. 같은 container shell을 계속 사용하세요.

Johnny42, 94% simulation policy, Co-Trained checkpoint는 Selected Policies를 확인하세요. 채점과 camera 호환성은 Sim Evaluation, 실제 robot은 같은 container에서 lerobot-rollout을 사용하는 Real Evaluation을 따릅니다.

lerobot-rollout은 --start_pose_dataset으로 지정한 dataset-derived pose로 이동한 뒤 P를 기다립니다. Model을 바꾸면 대응하는 training dataset으로 해당 옵션도 바꾸세요.

Rollout Control

시작 시 arm이 workshop 시작 pose로 움직인 뒤 P를 기다립니다. Rollout terminal에 focus를 두세요. Key는 대소문자를 구분하지 않습니다.

Key

동작

P

P for policy: 첫 trial 또는 다음 trial을 시작합니다.

S / F

성공/실패를 기록하고 시작 pose로 복귀한 뒤 일시 정지합니다.

N / →

N for next: Trial을 폐기하고 시작 pose로 복귀한 뒤 일시 정지합니다.

Q / Esc

Q for Quit: 종료하며 미완료 trial은 폐기합니다.

Ctrl+C

Rollout을 중단하고 cleanup을 실행합니다.

소품을 옮기기 전에 Paused를 기다리세요. 종료할 때도 cleanup과 복귀 동작이 끝난 뒤 arm을 만집니다.

Model 비교 시 terminal에 표시되는 첫 action 지연과 평가한 trial 중 성공 수를 기록하세요.

소품 reset 전에 Paused를 기다립니다. Recording을 켜면 채점된 trial이 저장됩니다. 기본 workshop strategy는 --duration을 무시하므로 직접 trial을 끝내세요. 실제 rollout 안내와 control을 참고하세요.

평가가 prompt로 돌아오면 실제 rollout이나 학습 전에 background server를 종료합니다.

kill "$POLICY_SERVER_PID"
wait "$POLICY_SERVER_PID" || true
unset POLICY_SERVER_PID

또는 container의 모든 policy server를 종료합니다.

pkill -f '[l]erobot\.async_inference\.policy_server'

Server가 준비되지 않으면 재시도 전에 tail -n 40 outputs/policy-server.log를 확인합니다. 전체 시작·종료 순서는 Sim Evaluation을 보세요.

자주 발생하는 문제#

증상

확인 사항

모든 motor가 보이지 않음

Arm에 맞는 전원과 연결 확인

Motor 하나가 보이지 않음

Motor cable 확인 후 power cycle

Camera 또는 serial index 변경

다시 탐지하고 저장 설정 갱신

Simulation image가 없음

--cameras all presets=newton,ovrtx_renderer 명시

Browser control이 반응하지 않음

Browser focus와 --browser-display 확인

Policy 연결 실패

Port 8080의 background server 준비 상태와 outputs/policy-server.log 확인

Dataset이 이미 존재함

--resume 또는 다른 --repo_id 사용

Troubleshooting을 확인하세요.
