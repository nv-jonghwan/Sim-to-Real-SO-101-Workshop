GR00T란?#

NVIDIA Isaac GR00T(Generalist Robot 00 Technology)는 범용 robot foundation model과 data pipeline을 개발해 humanoid robotics 연구·개발을 가속하는 연구 initiative이자 개발 플랫폼입니다.

다음 기능을 제공합니다.

  • 대규모 data로 학습한 Pre-trained visual understanding

  • 유연한 task 지정을 위한 Language-conditioned behavior

  • 실시간 robot 제어에 적합한 Action generation

이 과정에서는 SO-101용으로 post-train한 GR00T 1.7 model을 사용합니다.

참고

이 과정의 학습 시간

학습 시간은 hardware와 실행 설정에 따라 달라집니다. 직접 policy를 학습하거나 workshop에 제공된 호환 가능한 LeRobot GR00T 1.7 checkpoint를 사용하세요. 호환성은 Datasets and Models를 확인하세요.

Vision-Language-Action Model이란?#

Vision-Language-Action (VLA) models는 시각 입력, robot state, language instruction을 받아 robot 같은 embodied agent의 low-level 또는 mid-level action을 출력합니다.

Input: Camera image (1 or more) + Robot state + "Pick up the red vial and place it in the rack"
Output: Sequence of joint positions/velocities to execute the task

Modular Pipelines and Learned Policies#

Modular robot pipeline은 object pose 추정, motion planning, controller로 plan 전달을 순서대로 수행할 수 있습니다. VLA는 image, task text, robot state에서 action target으로의 mapping을 학습합니다. Vial placement에서는 observation마다 grasp-and-place plan을 직접 작성하는 대신, robot이 보고 수행한 예시로 policy를 학습합니다.

두 방식 모두 sensing, calibration, 안정적인 control이 필요합니다. 학습 기반 policy에는 demonstration coverage도 중요합니다. Instruction만으로는 익숙하지 않은 grasp에서 회복하는 방법을 배울 수 없습니다.

The Data Pyramid#

용어 정리#

Model weight, pre-training, post-training, fine-tuning, inference 자세히 보기

Model Weights and Parameters

Model weights 또는 parameters는 neural network 안에서 학습되는 수치입니다. 이 과정에서는 두 표현을 같은 의미로 사용합니다. Training은 weight를 조정하고 inference는 읽기만 합니다. Batch size나 learning rate 같은 Hyperparameters는 학습 전에 선택하며 weight update 방식을 제어합니다.

VLA 학습 단계 이해

VLA는 한 단계로 학습되지 않습니다. 앞 단계의 결과를 기반으로 여러 단계를 거칩니다.

이 단계를 이해하면 model이 폭넓은 세계 지식에서 특정 task의 robot 행동으로 발전하는 과정과 각 단계가 Sim-to-Real transfer에 중요한 이유를 알 수 있습니다.

Pre-training은 첫 번째이자 가장 큰 학습 단계입니다. Image, text, video와 점차 늘어나는 robot demonstration 등 internet 규모 data에서 일반적인 representation을 학습합니다.

특정 robot task에 적응하기 전에 재사용 가능한 visual, language, action representation을 만듭니다. 다양한 image·language·human video는 시각과 언어 지식을 제공하고, robot 경험은 observation과 action을 연결합니다. SO-101 demonstration은 arm, camera setup, vial-placement task의 세부 사항을 제공합니다. 이는 data의 역할을 설명하며 고정된 비율이나 보편적인 학습 순서를 뜻하지 않습니다.

Post-training은 pre-training 이후 일반 model을 특정 robot, task, environment에 유용하게 만드는 과정을 통칭합니다.

Observation과 language instruction을 robot action에 대응시키는 demonstration으로 pretrained foundation model을 특정 embodiment와 task에 맞춥니다. 연산량이 크며 일반적으로 GPU에서 수 시간이 필요합니다.

참고

이 과정에서 수행하는 단계입니다. Pretrained GR00T 1.7 foundation model을 simulation에서 수집한 SO-101 data에 맞게 조정합니다.

Fine-tuning은 더 작고 목적이 명확한 dataset으로 학습을 이어가 특정 조건의 성능을 개선하는 post-training 방식입니다.

예를 들어 simulation data로 post-train한 뒤 소량의 실제 robot demonstration으로 fine-tune해 Sim-to-Real gap을 줄일 수 있습니다. 일반 능력을 유지하면서 새로운 조건에 동작을 맞추는 것이 목표입니다.

Inference는 학습된 model을 실시간으로 실행하는 단계입니다. Camera frame과 language instruction을 받아 joint position command를 출력합니다.

Inference에서는 model weight가 고정되어 학습이 일어나지 않습니다. 한 번에 여러 timestep을 예측하는 action chunking은 forward pass 수를 줄이고 motion을 부드럽게 합니다. 현대 GPU에서는 실시간 closed-loop control을 지원합니다.

Training and Inference#

Training은 선택된 model weight를 바꾸고 inference는 새 observation에 저장된 weight를 사용합니다. Frozen component도 feature를 계산하지만 optimizer update는 받지 않습니다. 기본 recipe는 vision과 language를 freeze하며, 선택적인 vision-unfreezing 실험에서는 visual feature를 task image에 맞게 학습합니다. Trainable parameter가 늘면 memory가 더 필요하고 작은 dataset에 overfit될 수 있으므로 같은 조건의 rollout으로 판단하세요.

Architecture Overview#

GR00T 1.7은 image, language, robot state를 조건으로 action을 생성합니다. Vision-language backbone은 Cosmos-Reason2-2B이며 action head는 flow matching으로 action chunk를 생성합니다. GR00T 1.7 model card를 확인하세요.

개념적으로 System 2는 image와 language를 해석하고 System 1은 그 feature와 robot state로 action을 생성합니다. 이 용어는 GR00T dual-system architecture에서 유래합니다. Controller가 action을 적용하고 새 observation으로 loop를 닫습니다. 이 그림은 data flow를 설명하며 사람이 읽을 수 있는 plan을 반환한다는 뜻은 아닙니다.

GR00T 내부의 Cosmos-Reason2-2B backbone은 별도의 Cosmos 3 video augmentation demo와 다릅니다. 여기서는 action prediction용 feature를 제공하며, 뒤의 demo에서는 기록된 clip의 시각적 variation을 생성합니다.

주요 구성 요소#

Vision, language, action 구성 요소 자세히 보기

Vision Encoder: Camera image를 feature representation으로 처리

  • Object와 공간적 관계에 관한 시각적 근거 제공

  • Freeze하거나 workshop의 선택적 실험에서 학습 가능

Language Encoder: Task instruction 처리

  • 자연어를 task embedding으로 mapping

  • Visual observation과 함께 instruction으로 행동 조건 설정

Cross-Modal Fusion: Vision과 language 결합

  • Attention으로 visual feature와 language 연결

  • Language concept을 visual observation에 grounding

Action Decoder: Robot action 생성

  • 융합된 visual-language feature를 조건으로 사용

  • Joint position, velocity 등 적절한 action representation 출력

GR00T Training 한 Step에서 일어나는 일#

Training step은 episode나 robot 움직임이 아니라 optimizer update 한 번입니다. Batch가 observation/action window를 제공하고 GR00T가 loss를 계산해 trainable weight를 조정합니다.

Action head는 flow matching으로 noise에서 demonstration action chunk로 향하는 flow를 학습합니다. Training horizon은 sampled frame에서 시작하는 target window를 정하고, rollout horizon은 평가에 사용할 action 수를 정합니다.

검증한 sim-only 및 mixed HG-DAgger 20,000-step run은 H100 GPU 한 대에서 각각 약 12½시간과 13½시간이 걸렸습니다. Checkpoint 저장 시간은 포함하지만 dataset 준비, upload, 평가는 제외합니다. 시간은 recipe와 구현에 따라 달라집니다.

참고: 직접 Model Post-Training#

Workshop 중에는 학습 시간이 부족하므로 준비된 checkpoint를 사용합니다. 이 안내는 이후 post-training을 직접 진행할 때 사용하세요.

추후 실습용 학습 안내

Recording에 사용한 같은 so101-workshop container에서 실행합니다. 아래 명령은 Hugging Face repository ID로 LeRobot dataset을 읽습니다. 학습 전에 수집 process를 종료하세요.

  1. Teleoperating in Sim에 따라 dataset을 upload하고 검토합니다.

  2. Container 안에서 인증하고 run variable을 설정합니다.

hf auth login
wandb login
export HF_USER=your_hf_username
export DATASET_NAME=so101_teleop_vials_newton
export DATASET="${HF_USER}/${DATASET_NAME}"
export REPO_ID="${DATASET}_GR00T17"
export OUTPUT_DIR="outputs/train/${REPO_ID}"

실제 username과 dataset을 사용하세요. 자동 수집 data라면 DATASET, REPO_ID, OUTPUT_DIR을 정의하기 전에 DATASET_NAME=so101_auto_vials_newton으로 설정합니다. REPO_ID는 model repository 이름이고 OUTPUT_DIR은 host-mounted outputs/ 아래입니다. datasets/에만 저장된 dataset은 아래 Hub 기반 명령 전에 upload해야 합니다.

  1. 위 권장 설정으로 single-GPU post-training을 실행합니다.

lerobot-train --dataset.repo_id="$DATASET" --dataset.image_transforms.enable=true --policy.type=groot --policy.device=cuda --policy.base_model_path=nvidia/GR00T-N1.7-3B --policy.embodiment_tag=new_embodiment --policy.tune_visual=false --policy.tune_llm=false --policy.chunk_size=16 --policy.n_action_steps=16 --policy.use_relative_actions=true --policy.relative_exclude_joints='["gripper"]' --policy.use_bf16=true --policy.push_to_hub=true --policy.repo_id="$REPO_ID" --seed=42 --batch_size=32 --steps=20000 --save_checkpoint=true --save_freq=5000 --use_policy_training_preset=true --env_eval_freq=0 --eval_steps=0 --log_freq=10 --output_dir="$OUTPUT_DIR" --job_name="$DATASET" --wandb.enable=true --wandb.disable_artifact=true

20,000 step, 5,000 step마다 checkpoint 저장, image augmentation, BF16, Hub upload를 사용합니다. GPU memory가 부족하면 batch size를 줄이세요. Local artifact만 원하면 --policy.push_to_hub=false, Weights & Biases 없이 학습하려면 --wandb.enable=false를 사용합니다.

Multi-GPU Training

대안인 Multi-GPU 학습 명령 보기

여러 GPU가 보이는 machine에서는 3단계 대신 같은 설정으로 Accelerate를 실행할 수 있습니다. 한 run에서는 single-GPU 또는 이 명령 중 하나를 선택하세요. 별도 실험에는 새 OUTPUT_DIR을 사용합니다.

accelerate launch --multi_gpu --num_processes="$(nvidia-smi -L | wc -l)" "$VIRTUAL_ENV/bin/lerobot-train" --dataset.repo_id="$DATASET" --dataset.image_transforms.enable=true --policy.type=groot --policy.device=cuda --policy.base_model_path=nvidia/GR00T-N1.7-3B --policy.embodiment_tag=new_embodiment --policy.tune_visual=false --policy.tune_llm=false --policy.chunk_size=16 --policy.n_action_steps=16 --policy.use_relative_actions=true --policy.relative_exclude_joints='["gripper"]' --policy.use_bf16=true --policy.push_to_hub=true --policy.repo_id="$REPO_ID" --seed=42 --batch_size=32 --steps=20000 --save_checkpoint=true --save_freq=5000 --use_policy_training_preset=true --env_eval_freq=0 --eval_steps=0 --log_freq=10 --output_dir="$OUTPUT_DIR" --job_name="$DATASET" --wandb.enable=true --wandb.disable_artifact=true

학습한 Policy 선택

  1. 학습이 끝나면 upload한 model repository를 선택합니다.

export MODEL_ID="$REPO_ID"

또는 outputs/train/<user>/<model>/checkpoints/ 아래의 local pretrained_model directory를 선택합니다. 전체 training run directory가 아니라 policy configuration, weight, processor가 들어 있는 directory를 사용하세요. --policy.push_to_hub=false로 학습한 경우에도 사용할 수 있습니다.

Local checkpoint에는 weight뿐 아니라 configuration과 processor artifact도 필요합니다. Checkpoint Compatibility를 확인하세요. 학습 완료 후 같은 container terminal에서 평가를 계속합니다. Shell을 다시 열었다면 일반 export 변수는 유지되지 않으므로 MODEL_ID를 다시 설정하세요.

선택 사항: Vision Encoder Unfreeze

--policy.tune_visual=true로 vision encoder를 학습하고 --policy.tune_llm=false로 language backbone을 freeze합니다. Frozen-vision run은 --policy.tune_visual=false를 사용합니다. 이 flag는 학습 중 update할 parameter를 정하며 inference 설정을 바꾸지 않습니다.

선택된 94% simulation policy는 vision trainable, language frozen, batch size 32, 32-step action window를 사용했습니다. 아래 예시는 이 선택으로 GR00T base에서 새 run을 시작합니다. 전체 recipe와 benchmark 조건은 model card를 확인하세요.

Vision-Unfrozen 학습 예시 보기

위에서 DATASET, DATASET_NAME을 설정하고 인증한 뒤 대안 single-GPU 실험을 실행합니다. 별도 model 이름과 output directory를 사용해 frozen-vision run을 비교용으로 보존합니다.

export VISION_REPO_ID="${DATASET}_GR00T17_vision"
lerobot-train --dataset.repo_id="$DATASET" --dataset.image_transforms.enable=true --policy.type=groot --policy.device=cuda --policy.base_model_path=nvidia/GR00T-N1.7-3B --policy.embodiment_tag=new_embodiment --policy.tune_visual=true --policy.tune_llm=false --policy.chunk_size=32 --policy.n_action_steps=32 --policy.use_relative_actions=true --policy.relative_exclude_joints='["gripper"]' --policy.use_bf16=true --policy.push_to_hub=true --policy.repo_id="$VISION_REPO_ID" --seed=42 --batch_size=32 --steps=20000 --save_checkpoint=true --save_freq=5000 --use_policy_training_preset=true --env_eval_freq=0 --eval_steps=0 --log_freq=10 --output_dir="outputs/train/$VISION_REPO_ID" --job_name="${DATASET_NAME}_vision" --wandb.enable=true --wandb.disable_artifact=true

학습 후 export MODEL_ID="$VISION_REPO_ID"로 평가할 model을 선택합니다. 이 예시의 학습 window는 32-step이지만 평가는 과정의 16-action rollout 설정을 사용하세요.

이 예시는 vision 학습뿐 아니라 batch size와 action window도 바꿉니다. Unfreezing의 효과만 보려면 두 run 모두 batch size 32와 32-step window를 사용하고 dataset, optimizer 설정, update 수, 평가 조건을 동일하게 유지하세요. Unfreezing에는 더 많은 memory가 필요하며 성능 향상을 보장하지 않습니다.

실험 방법: Checkpoint 학습 이어가기#

기존 update를 반복하지 않고 policy를 더 학습할 수 있습니다. 예를 들어 50,000-step checkpoint에서 20,000 update를 추가해 효과를 살펴봅니다. 원본 checkpoint를 보존하고 같은 평가 조건으로 비교하세요. 추가 학습은 개선, 변화 없음, overfitting 중 어느 결과로도 이어질 수 있습니다.

Checkpoint continuation, Optimizer State, Data Mixture 자세히 보기

복원할 상태 선택

  • Training run resume: Weight, optimizer state, scheduler state, update counter를 복원합니다. 중단된 run에 적합하며 exported policy만이 아니라 training state를 포함한 전체 checkpoint가 필요합니다. --steps=70000은 전체 목표이므로 50,000에서 재개하면 20,000 update가 남습니다. 완료된 run을 연장할 때는 learning-rate schedule을 확인하세요. 이미 0에 가깝게 감소했다면 추가 학습 효과가 작을 수 있습니다.

  • 저장 Weight로 새 Fine-Tuning run 시작: Policy와 저장된 processor를 읽고 새 optimizer와 schedule을 만듭니다. --resume=false에서 --steps=20000은 새 run의 0부터 세는 추가 update 20,000회를 뜻합니다. 새 recipe나 실제 demonstration을 도입할 때 유용합니다.

LeRobot에서 --policy.path는 학습된 policy와 configuration을 선택하며, resolved configuration에는 pretrained_path로 기록됩니다. GR00T의 base_model_path는 기반 foundation-model asset을 지정합니다. 호환되는 base-model revision, camera key, joint 순서, action representation, horizon, processor를 유지하세요.

예시: Update 20,000회 추가

Workshop container에서 실행합니다. CHECKPOINT에 weight, policy configuration, processor, train_config.json이 있는 실제 LeRobot pretrained_model directory를 지정하세요. 기존 training configuration과 dataset을 재사용하되 output directory와 optimizer는 새로 만듭니다. Dataset과 base-model 경로가 container에서 접근 가능한지 확인하세요.

export CHECKPOINT="outputs/train/your_hf_username/your_model/checkpoints/050000/pretrained_model"
export CONTINUE_OUTPUT="outputs/train/your_hf_username/your_model_continue20k"
lerobot-train --config_path="$CHECKPOINT/train_config.json" --policy.path="$CHECKPOINT" --resume=false --steps=20000 --use_policy_training_preset=true --policy.optimizer_lr=1e-5 --policy.max_steps=20000 --policy.warmup_ratio=0.05 --policy.push_to_hub=false --save_checkpoint_to_hub=false --save_checkpoint=true --save_freq=5000 --output_dir="$CONTINUE_OUTPUT" --job_name=continue20k --wandb.enable=false

Peak learning rate 1e-5와 warmup 5%는 실험 설정이며 검증된 최적값이 아닙니다. 이 preset에서는 policy.max_steps가 warmup 계산에, 바깥쪽 steps가 update 수에 사용됩니다. 새 020000 checkpoint는 이전 50,000회와 추가 20,000회 update를 거친 결과입니다. Batch size, augmentation, frozen component는 저장된 configuration에서 가져오므로 실행 전에 resolved setting을 확인하세요.

예시: Gripper Mapping 맞추기

Encoder calibration이 다르면 같은 gripper percent가 다른 실제 opening을 뜻할 수 있습니다. 수집과 simulation inference는 기본 1485-tick의 utils/gripper_calibration.py를 공유합니다. 이전 1531-tick span으로 학습한 model임이 확인되면 일반 lerobot_eval 명령에 --gripper_span_ticks 1531을 추가하세요. Observation과 action 변환 모두 이 span을 사용하고 5개 arm 좌표는 그대로입니다. 같은 jaw-angle zero를 가정한 override입니다.

측정한 robot mapping으로도 weight를 바꾸지 않고 gripper 값을 변환할 수 있습니다. 아래는 계산만 수행하며 robot에 연결하거나 움직이지 않습니다.

1from sim_to_real_so101.utils.gripper_calibration import GripperCalibration
2
3model = GripperCalibration(span_ticks=1531)  # Known training convention.
4robot = GripperCalibration()  # Workshop default; replace with measured span/zero.
5model_command = 45.0
6robot_command = robot.degrees_to_percent(model.percent_to_degrees(model_command))
7model_observation = model.degrees_to_percent(robot.percent_to_degrees(robot_command))
8print(robot_command, model_observation)  # About 46.39%, then 45%.

배포에서는 policy state normalization 전과 action decoding 후에 이 계산을 적용합니다. 예시가 lerobot-rollout에 자동 설치되지는 않습니다. 같은 frame에서 encoder span과 실제 jaw-angle zero를 측정하고 driver limit을 유지하세요. Gripper 좌표를 맞추는 것으로 다른 arm offset이나 실제 task 성공까지 해결·입증되지는 않습니다.

새 Optimizer가 더 좋을까?

Model weight는 학습된 행동을 저장합니다. Adam optimizer state는 이후 update 방향을 정하는 gradient 방향과 크기의 이동 추정값을 저장합니다. 이를 초기화해도 weight는 보존됩니다.

Simulation-only에서 sim/real mixture로 바꾸면 gradient distribution이 달라져 reset이 도움이 될 수 있습니다. 반면 유용한 이력을 잃고 초기 update가 불안정해질 수도 있습니다. 같은 objective와 data로 계속 학습할 때는 state 유지가 유용할 수 있습니다. 어느 쪽도 성능 향상을 보장하지 않습니다.

Optimizer reset과 learning-rate restart는 별개의 선택입니다. Adam을 reset하지 않아도 감소한 learning rate를 다시 유효한 값으로 쓰는 것이 중요할 수 있습니다. Reset 자체를 비교하려면 동일 weight에서 시작하고 batch, trainable parameter, update 수, learning-rate schedule을 맞춘 뒤 optimizer state 복원 여부만 바꾸세요. 추가 학습·reset·schedule 변경을 함께 하면 recipe 전체를 평가하는 실험입니다.

실제 Data 추가: Sampling Ratio 제어

Simulation checkpoint에서 mixed sim/real data로 이어 학습하거나, pretrained GR00T에서 처음부터 mixture를 사용할 수 있습니다. 전자는 task 학습을 재사용하고 후자는 실제 예시를 일찍 접합니다. 비교 시 첫 단계의 비용과 data 노출도 고려하세요. 실제 data만으로 이어 학습하는 것은 별도 실험이며 작은 dataset에 overfit될 수 있습니다.

Sampling ratio는 저장한 demonstration 수와 별개로 각 source를 뽑는 빈도를 정합니다. Batch size 32에서 real/sim 50%씩이면 평균 약 16개씩, real 25%면 약 8개입니다. Weighted sampler는 많은 추출에 걸쳐 비율을 맞추고, 고정 batch 구성은 정확한 수를 강제할 수 있습니다.

Source 내부 uniform sampling에서는 eligible real frame마다 p_real / N_real, simulation frame마다 (1 - p_real) / N_sim의 weight를 줍니다. N_real과 N_sim은 episode가 아니라 학습 가능한 frame 수입니다. Real sampling을 늘리면 제한된 실제 예시를 더 자주 보지만 새로운 다양성이 생기지는 않습니다. 실제 sampling 비율과 overfitting을 기록하세요.

참고

비율 설정 전에 Trainer를 확인하세요. 이 실습의 LeRobot v0.6.0 training path는 eligible frame을 shuffle하며 sim/real mixture-ratio flag가 없습니다. GR00T의 balance_dataset_weights, balance_trajectory_weights도 이 경로에서는 쓰지 않습니다. Dataset merge만으로 선택한 비율이 강제되지 않으며 긴 episode가 더 많은 frame을 제공합니다. 명시적 비율에는 source별 weighting과 frame source identity를 지원하는 trainer 또는 sampler가 필요합니다. 위 weight는 실험 설계이며 예시의 추가 CLI 옵션이 아닙니다.

의미 있는 비교 만들기

일부 demonstration을 test용으로 남기고, 학습이나 입력·action normalization 통계 계산에도 사용하지 마세요. 보지 못한 demonstration과 예측을 비교하는 것이 held-out validation입니다. Rollout test는 model이 arm을 제어해 task를 완료하는지 측정합니다. 두 검사는 다른 것을 측정하므로 prediction error가 줄어도 task 성공은 나빠질 수 있으며 그 반대도 가능합니다.

원본 checkpoint, 같은 data와 trainable component로 이어 학습한 대조군, 제안 변경을 동일 조건으로 비교하세요. 추가 update의 효과와 unfreezing 또는 real data의 효과를 구분하는 데 도움이 됩니다. 한 번에 한 요인을 바꾸고 전체 update 및 source별 sampled example 수를 기록하며, Sim-to-Real 주장은 실제 task에서도 검증하세요.

구현은 LeRobot training configuration과 frame sampler를 참고하세요. Adam paper는 optimizer state를, Sim-and-Real Co-Training은 data-mixture 선택을 다룹니다. Workshop data workflow는 Co-Training in Practice로 이어집니다.

Overfitting#

학습을 많이 한다고 항상 좋아지는 것은 아닙니다. Training loss가 줄어도 held-out demonstration이나 새 rollout 조건의 성능이 나빠지면 overfitting일 수 있습니다. Loss만으로 선택하지 말고 중간 checkpoint를 평가하세요. 개선이 멈추면 step을 늘리기 전에 실패를 분석하고 demonstration coverage를 보완합니다.

Vial을 gripper의 정확히 익숙한 위치로 옮기기 전까지 policy가 멈추는 모습을 보세요. **Grasp 주변의 Domain Randomization (DR)**이 부족하면 model이 좁은 범위의 익숙한 view에 의존할 수 있습니다.

Demonstration의 vial 위치와 grasp angle을 다양하게 하고 학습하지 않은 위치를 시험하세요. 같은 grasp의 episode만 늘려서는 부족한 다양성을 채울 수 없습니다.

핵심 내용#

  • Distribution 안에서 시작하세요. Gripper opening을 포함해 checkpoint의 training dataset에 나타나는 starting pose를 사용합니다. 기본 home pose가 맞다고 가정하지 말고 실제 demonstration을 확인하세요. 익숙하지 않은 시작은 camera view와 robot state를 바꾸므로 잘 학습된 policy도 실패할 수 있습니다.

  • GR00T는 System 2 vision-language backbone으로 image와 instruction을 해석하고, System 1 action head로 그 feature와 robot state를 조건으로 action chunk를 생성합니다.

  • VLA는 하나의 architecture에서 vision, language, action을 결합합니다.

  • GR00T는 학습을 가속하는 pretrained component를 제공합니다.

  • Action chunking은 부드럽고 시간적으로 일관된 control을 제공합니다.

  • Pretrained vision encoder는 visual generalization을 지원합니다.

Action Space and Control#

Action Representations#

Joint action, End-Effector action, Action Chunking 비교

GR00T는 여러 action representation을 지원합니다.

Joint Position Actions

  • Robot configuration 직접 제어

  • 전체 arm의 협응 학습 필요

End-Effector Actions

  • Inverse kinematics로 joint command 계산

  • Arm configuration을 추상화

Action Chunking

  • 여러 미래 action을 한 번에 예측

  • 더 부드러운 실행과 시간적 일관성

이 과정은 joint position actions with action chunking을 사용합니다. Arm action은 관측된 joint position에 대한 relative 값입니다.

Prediction과 Execution 길이

Training chunk는 observation에 대응하는 미래 action target을, rollout horizon은 다음 chunk 요청 전에 사용하는 예측 sequence 길이를 나타냅니다.

**Real-time chunking (RTC)**은 prediction delay를 고려해 연속 action chunk를 연결하도록 돕습니다.

선택된 policy와 선택적 vision-unfrozen 예시를 포함해 workshop 전체에서 16-action rollout horizon을 사용하세요.

Training과 Inference Loop 살펴보기#

그림을 조절해 관계를 살펴보세요. 실제 training run이나 robot controller가 아닌 교육용 illustration입니다. 계산은 예시의 16-step training window와 gradient accumulation 없음에 기반합니다. Rollout timeline은 기준 30 Hz를 사용하며 inference 및 network delay는 제외합니다.

Training: 여러 예시로 한 번의 weight update 수행

Sampling한 각 예시는 이미지, instruction, robot state를 이후 action window와 짝짓습니다. Loss를 기반으로 학습 대상 weight를 갱신합니다.

  1. Sample windows32 windows / updateImages + instruction + state
  2. Prepare targets16 future action stepsImage augmentation은 선택 사항
  3. Compute lossGR00T flow matchingNoise가 포함된 action target으로 학습
  4. Update weightsOptimizer + learning rate20,000번 update 반복

다음 update: 새 batch sampling → loop 반복

32 windows / update = 32 × 1 GPU process

640,000 sampled windows를 전체 run에서 사용 = 32 × 20,000 updates

Window는 겹치거나 반복될 수 있습니다. 이 값은 고유 demonstration 수나 training 시간의 예측값이 아닙니다. 같은 batch 설정에서 GPU 수를 늘리면 속도뿐 아니라 학습에 사용되는 data의 양도 달라집니다.

Inference: 관찰 → 예측 → 실행 → 다시 관찰

로봇이 33 ms마다(30 Hz) action 하나를 실행한다고 가정합니다. 각 예측에서 사용하는 action 수를 줄이면 새 예측이 더 자주 필요합니다. Control rate는 그대로 유지됩니다.

  1. ObserveTwo cameras + joint stateTask instruction 유지
  2. Predict a chunkTrained window: 16 stepsFrozen weights + saved processors
  3. Execute actions16 actions 실행Control rate: 30 Hz
  4. Observe again새 예측으로 보충선택한 action을 모두 실행한 뒤

동일한 시간에 같은 32 actions 실행 30 Hz에서 0 → 1.07초

▼···············▼···············

▼ 새 prediction · 각 cell은 실행한 action 하나를 표시

533 ms 간격으로 prediction 수행 = 16 actions ÷ 30 Hz

초당 1.88 predictions입니다. 8 actions를 사용하면 두 배인 3.75가 됩니다.

Timing 설명을 위한 예시입니다. 예측이 즉시 완료되고 이전 action을 모두 실행하면 새 chunk를 요청한다고 가정합니다. 실제 inference 지연으로 멈추는 구간이 생길 수 있습니다. Workshop rollout command는 16 actions로 유지하세요.
