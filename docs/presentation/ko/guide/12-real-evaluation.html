실제 Robot 평가#

Hands-on
이 Module에 필요한 준비물

실습입니다. Calibration된 follower, camera 두 대, 조립한 workspace, 실행 중인 so101-workshop container, simulation에서 평가한 checkpoint가 필요합니다.

학습 목표#

  • 실제 robot에서 sim-only와 real-only data로 학습한 policy를 비교해 Sim-to-Real gap을 살펴봅니다.

  • State-machine 및 human teleoperation 등 서로 다른 simulation data로 학습한 policy를 비교합니다.

  • State-machine data의 overfitting이 robustness를 제한하고 demonstration의 motion pattern과 정지 행동을 반복하게 하는 방식을 이해합니다.

Workspace 준비#

실행 전에 Safety 절차를 확인하세요.

  1. Mat에 vial 1–3개를 놓고 rack을 기준 위치에 배치합니다.

  2. 수집 시 camera view와 lightbox 설정을 맞춥니다.

첫 번째 Policy: Sim-Only Data로 학습#

  1. Simulation 평가와 background server를 종료한 뒤 같은 container terminal에서 계속합니다.

Container Shell 재접속

실행 중인 workshop container에 다시 접속하려면 host terminal에서 다음을 실행합니다.

docker exec -it so101-workshop bash

docker ps의 NAMES에서 so101-workshop을 찾아 실행 여부를 확인합니다. 이미 container prompt에 있다면 건너뜁니다.

  1. Container에서 simulation에 사용한 model을 선택합니다. 확인한 camera index를 재사용하세요.

export MODEL_ID=sreetz-nv/so101_newton_dr500_vision_h32_b32_20k_20260929
export TASK_INSTRUCTION="Pick up the vial and place it in the rack"
export ROBOT_CAMERAS="{ wrist: {type: opencv, index_or_path: $CAMERA_GRIPPER, width: 640, height: 480, fps: 30, fourcc: MJPG}, external: {type: opencv, index_or_path: $CAMERA_EXTERNAL, width: 640, height: 480, fps: 30, fourcc: MJPG} }"

예상되는 동작#

Simulation의 state-machine demonstration 500개로 학습했으며 teleoperation이나 실제 demonstration은 포함하지 않았습니다.

“Return to home” demonstration이 없어 episode 끝에서 vial을 놓은 위치에 머뭅니다. 특정 vial 위치에 편향되고 motion 다양성이 부족한 overfitting이 있습니다.

중요

State-machine demonstration의 특정 grasp와 vial 위치에 overfit되었으므로 실제 robot에서는 낮은 성공률을 예상합니다.

선택 사항: 먼저 Simulation에서 시험

  1. 실제 rollout을 종료한 뒤 같은 container terminal을 사용합니다. MODEL_ID와 task instruction은 유지합니다.

  2. 아래 simulation policy server를 시작하거나 이미 실행 중이면 재사용합니다.

mkdir -p outputs
python -m lerobot.async_inference.policy_server --host=0.0.0.0 --port=8080 --fps=30 --inference_latency=0 > outputs/policy-server.log 2>&1 & POLICY_SERVER_PID=$!
python -c "import grpc; grpc.channel_ready_future(grpc.insecure_channel('localhost:8080')).result(timeout=60); print('Policy server ready')"

  1. Policy server ready를 기다린 뒤 평가를 실행합니다.

lerobot_eval --task Newton-So101-Teleop-Vials-To-Rack-DR-Eval-v0 --cameras all --browser-display presets=newton,ovrtx_renderer --server_address localhost:8080 --pretrained_name_or_path "$MODEL_ID" --policy_type groot --policy_device cuda --start_pose_dataset sreetz-nv/so101_newton_dr500_20260923 --action_horizon 16 --num_episodes 10 --seed 76000 --lang_instruction "$TASK_INSTRUCTION"

  1. http://localhost:8090을 엽니다. Viewer에는 browser tab 하나만 연결하세요.

  2. 실제 policy를 실행하기 전에 background server를 종료합니다. 평가가 실행 중이면 먼저 Ctrl+C를 누르세요.

kill "$POLICY_SERVER_PID"
wait "$POLICY_SERVER_PID" || true
unset POLICY_SERVER_PID

또는 container의 모든 policy server를 종료합니다.

pkill -f '[l]erobot\.async_inference\.policy_server'

다른 terminal의 server를 재사용했다면 해당 terminal에서 종료합니다. 아래 실제 rollout은 policy를 직접 로드합니다.

  1. 실제 robot에서 interactive rollout을 실행합니다.

lerobot-rollout --strategy.type=workshop --policy.path="$MODEL_ID" --policy.base_model_path=nvidia/GR00T-N1.7-3B --policy.n_action_steps=16 --robot.type=so101_follower --robot.port="$ROBOT_PORT" --robot.id="$ROBOT_ID" --robot.use_degrees=true --robot.cameras="$ROBOT_CAMERAS" --task="$TASK_INSTRUCTION" --device=cuda --display_data=true --inference.type=rtc --inference.rtc.enabled=false --inference.rtc.execution_horizon=16 --inference.queue_threshold=0 --start_pose_dataset=sreetz-nv/so101_newton_dr500_20260923

Model 비교 시 terminal에 표시되는 첫 action 지연과 평가한 trial 중 성공 수를 기록하세요.

팁

첫 rollout에서 camera 구도를 확인하세요. P를 누르기 전에 external preview에 rack 대부분과 robot 일부, vial pickup area가 보이는지 확인합니다. Camera 각도를 이미 맞췄다면 robot이 paused일 때 소품을 화면 안으로 옮기세요. FoV가 좁아 소품 위치가 중요합니다. Policy가 잘 동작하지 않으면 model을 바꾸기 전에 구도부터 확인하세요.

명령 Flag 이해

Policy 반환 길이는 --policy.n_action_steps=16, 별도의 RTC 설정은 --inference.rtc.execution_horizon=16을 사용합니다. 각 model의 training data에 맞는 instruction을 사용하세요. Async inference engine을 선택하되 RTC compensation은 끕니다.

--robot.use_degrees=true는 arm joint를 degree로 유지해 기록된 state/action과 맞춥니다. Gripper는 percent 규약을 사용합니다.

Arm은 sreetz-nv/so101_newton_dr500_20260923의 평균 episode-start pose로 자동 이동한 뒤 P를 기다립니다. 시작 중 경로를 비우세요. Terminal에 dataset-derived 평균과 표준편차가 표시됩니다. P를 누르기 전에 실제 pose를 확인하세요. 평균 계산만으로 시작 조건 일치가 입증되지는 않습니다.

Starting pose는 초기 camera view, 도달 가능한 motion, GR00T relative action의 trajectory를 결정합니다. Training-start distribution 밖이면 weight와 무관하게 유능한 policy도 실패할 수 있습니다. 비교 전에 실제 pose와 현재 gripper calibration을 확인하세요. Offset이 필요하거나 distribution과 다르다면 matched evaluation이 아닌 out-of-distribution test로 표시합니다.

첫 action을 보낼 때 Waiting | first policy action 다음에 Running | first policy action after ... s가 표시됩니다. 기본 workshop strategy는 Q, Esc, Ctrl+C까지 실행하며 --duration은 무시합니다.

예상되는 동작#

실제 demonstration 50개로 학습한 model입니다. 본인의 station에서 simulation 기반 policy와 비교하세요.

Camera 이름 표준화 이전에 수집한 data여서 external camera 이름이 front입니다. 이후 다른 model rollout의 ROBOT_CAMERAS export를 실행해 external로 되돌리세요.

선택 사항: 먼저 Simulation에서 시험

  1. 실제 rollout을 종료한 뒤 같은 container terminal을 사용합니다. MODEL_ID와 task instruction은 유지합니다.

  2. 아래 simulation policy server를 시작하거나 이미 실행 중이면 재사용합니다.

mkdir -p outputs
python -m lerobot.async_inference.policy_server --host=0.0.0.0 --port=8080 --fps=30 --inference_latency=0 > outputs/policy-server.log 2>&1 & POLICY_SERVER_PID=$!
python -c "import grpc; grpc.channel_ready_future(grpc.insecure_channel('localhost:8080')).result(timeout=60); print('Policy server ready')"

  1. Policy server ready를 기다린 뒤 평가를 실행합니다.

lerobot_eval --task Newton-So101-Teleop-Vials-To-Rack-DR-Eval-v0 --cameras all --browser-display presets=newton,ovrtx_renderer --server_address localhost:8080 --pretrained_name_or_path "$MODEL_ID" --policy_type groot --policy_device cuda --start_pose_dataset sreetz-nv/so101-clean-up-vials-into-rack-50_20260628_131121 --action_horizon 16 --num_episodes 10 --seed 76000 --lang_instruction "$TASK_INSTRUCTION" --rename_map '{"external":"front"}'

  1. http://localhost:8090을 엽니다. Viewer에는 browser tab 하나만 연결하세요.

  2. 실제 policy를 실행하기 전에 background server를 종료합니다. 평가가 실행 중이면 먼저 Ctrl+C를 누르세요.

kill "$POLICY_SERVER_PID"
wait "$POLICY_SERVER_PID" || true
unset POLICY_SERVER_PID

또는 container의 모든 policy server를 종료합니다.

pkill -f '[l]erobot\.async_inference\.policy_server'

다른 terminal의 server를 재사용했다면 해당 terminal에서 종료합니다. 아래 실제 rollout은 policy를 직접 로드합니다.

같은 model로 실제 평가를 실행합니다.

lerobot-rollout --strategy.type=workshop --policy.path="$MODEL_ID" --policy.base_model_path=nvidia/GR00T-N1.7-3B --policy.n_action_steps=16 --robot.type=so101_follower --robot.port="$ROBOT_PORT" --robot.id="$ROBOT_ID" --robot.use_degrees=true --robot.cameras="$ROBOT_CAMERAS" --task="$TASK_INSTRUCTION" --device=cuda --display_data=true --inference.type=rtc --inference.rtc.enabled=false --inference.rtc.execution_horizon=16 --inference.queue_threshold=0 --start_pose_dataset=sreetz-nv/so101-clean-up-vials-into-rack-50_20260628_131121

Rollout Control

시작 시 arm이 workshop 시작 pose로 움직인 뒤 P를 기다립니다. Rollout terminal에 focus를 두세요. Key는 대소문자를 구분하지 않습니다.

Key

동작

P

P for policy: 첫 trial 또는 다음 trial을 시작합니다.

S / F

성공/실패를 기록하고 시작 pose로 복귀한 뒤 일시 정지합니다.

N / →

N for next: Trial을 폐기하고 시작 pose로 복귀한 뒤 일시 정지합니다.

Q / Esc

Q for Quit: 종료하며 미완료 trial은 폐기합니다.

Ctrl+C

Rollout을 중단하고 cleanup을 실행합니다.

소품을 옮기기 전에 Paused를 기다리세요. 종료할 때도 cleanup과 복귀 동작이 끝난 뒤 arm을 만집니다.

Model 비교 시 terminal에 표시되는 첫 action 지연과 평가한 trial 중 성공 수를 기록하세요.

핵심 내용#

  • 특정 grasp와 vial 위치에 overfit되면 simulation 성공률은 높아도 실제 성능은 안정적이지 않을 수 있습니다.

  • 첫 policy의 state-machine demonstration에는 release 후 복귀가 없어 완전한 반복 loop를 배우지 못했습니다.

  • 두 번째 policy의 teleoperation demonstration은 placement 후 동작까지 포함합니다. Ready pose 복귀와 다음 pickup으로 이어지는지 관찰하세요.

  • 학습된 복귀와 S/F 또는 N 뒤 rollout controller의 homing은 다릅니다. Trial을 끝내기 전에 policy 자체의 동작을 비교하세요.

  • 각 policy의 training data에 시작 pose를 맞추고 관찰한 행동을 기록합니다.
