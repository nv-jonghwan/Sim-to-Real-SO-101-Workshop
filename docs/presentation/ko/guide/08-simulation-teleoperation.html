Simulation에서 Teleoperation#

Hands-on
이 Module에 필요한 준비물

실습입니다. so101-workshop container, calibration된 SO-101 leader arm, Isaac Lab simulation용 NVIDIA GPU가 필요합니다.

실제 robot에서 teleoperation을 해봤으니, 이제 Isaac Lab의 _simulation_에서 진행합니다.

Leader arm으로 simulation의 SO-101을 제어하고 Isaac Lab에서 demonstration을 수집합니다.

Simulation에서는 환경을 직접 제어할 수 있습니다. 예를 들어 Domain Randomization으로 dataset의 다양성을 확보할 수 있습니다.

학습 목표#

  • Leader arm으로 simulation의 SO-101 제어

  • Wrist 및 external camera view로 vial 배치 연습

  • Demonstration 기록·검토 및 선택적인 upload

  • State machine 기반 scripted collection 탐색

Teleoperation: Human Demonstration 수집#

이 실습에서는 teleoperation 중 Domain Randomization을 적용합니다. 수집한 data는 _Imitation Learning_이라는 robot learning 방식에 사용합니다.

Imitation Learning을 사용하는 이유(펼쳐 보기)

Teleoperation은 task 수행 중 사람의 전문성을 action으로 기록해 자연스럽고 직관적인 motion을 학습에 활용할 수 있게 합니다.

사람은 task 성공에 중요한 요소를 직관적으로 알기 때문에 demonstration에 작업의 핵심이 반영됩니다.

사람마다 같은 task에 접근하는 방식이 달라 다양성도 생깁니다. Imitation Learning에 사용하기 전에 task 성공 여부와 명확하고 목적 있는 motion인지 검토하세요.

Workshop Container 실행#

  1. 앞 실습의 so101-workshop container terminal을 사용합니다. 실제 teleoperation이 실행 중이면 Ctrl+C로 중단하고 종료를 기다린 뒤 simulation을 시작하세요.

Workshop Container 시작 또는 재접속

Container가 실행 중이 아니라면 host terminal에서 workshop checkout을 사용해 시작합니다.

cd ~/Sim-to-Real-SO-101-Workshop

위 cd 명령에는 실제 저장소 경로를 사용하세요. ~/Sim-to-Real-SO-101-Workshop는 예시입니다. 같은 터미널에서 현재 폴더에 docker/Dockerfile과 source/가 있는지 확인한 뒤 다음 명령 블록을 실행하세요.

xhost +
docker run --name so101-workshop -it --rm --privileged --runtime=nvidia --network=host -e DISPLAY -v /tmp/.X11-unix:/tmp/.X11-unix -v ~/.Xauthority:/root/.Xauthority -v /dev:/dev -v /run/udev:/run/udev:ro -v ~/.cache/huggingface:/root/.cache/huggingface -v ~/.cache/ovrtx:/root/.cache/ovrtx -v ~/.cache/warp:/root/.cache/warp -v ./docker/env:/root/env -v ./source:/workspace/Sim-to-Real-SO-101-Workshop/source -v ./outputs:/workspace/Sim-to-Real-SO-101-Workshop/outputs -v ./datasets:/workspace/Sim-to-Real-SO-101-Workshop/datasets -v ./models:/workspace/Sim-to-Real-SO-101-Workshop/models so101-workshop:latest

이미 실행 중인데 다시 접속해야 한다면 host terminal에서 다음을 사용합니다.

docker exec -it so101-workshop bash

이후 명령은 container terminal에서 계속 실행합니다. Python environment와 저장된 설정이 자동으로 로드됩니다.

Simulation Teleoperation 연습#

연습과 recording에는 Newton-So101-Teleop-Vials-To-Rack-DR-v0를 사용합니다.

  1. TELEOP_PORT와 TELEOP_ID가 calibration한 leader와 맞는지 확인합니다. Agent는 이 설정을 자동으로 읽습니다.

  2. Simulation 소품과 간섭하지 않는 작은 pose로 leader arm을 옮깁니다.

  3. Container 안에서 simulation을 실행합니다.

lerobot_agent --task Newton-So101-Teleop-Vials-To-Rack-DR-v0 --cameras all --browser-display presets=newton,ovrtx_renderer
Simulation Environment 선택지 비교

--task의 task ID로 scene과 randomization을 선택합니다. 수집용 variant는 lerobot_agent 또는 vials_state_machine, 평가용 variant는 lerobot_eval과 사용합니다.

Environment

변경되는 요소

사용 시점

Newton-So101-Teleop-Vials-To-Rack-v0

Object 배치가 randomize되는 기본 vial-to-rack scene

Teleoperation 연습 및 수집 baseline 확보

Newton-So101-Teleop-Vials-To-Rack-DR-v0

Material·lighting variation, film grain, wrist blur, 더 넓은 mat variation 추가

다양한 simulation 조건에서 demonstration 수집

Newton-So101-Teleop-Vials-To-Rack-Eval-v0

평가 성공 시 종료하는 기본 scene

Simulation의 baseline policy 동작 측정

Newton-So101-Teleop-Vials-To-Rack-DR-Eval-v0

평가 성공 시 종료하는 standard DR scene

Standard randomization에 대한 robustness 평가

Appearance components: 모든 vial task는 matte foam, 종이와 비슷한 vial body, blue-gray wall, 기본 camera grading/tone mapping을 사용합니다. DR은 material과 lighting variation, camera별 film grain, wrist 전용 blur를 추가합니다. Display, recording, policy observation은 같은 처리된 RGB를 사용합니다. 이 설정은 camera 외관을 근사하므로, 실제 transfer는 simulation과 실제 환경의 policy 동작을 비교해 측정하세요.

ovrtx 첫 실행은 shader cache 준비에 몇 분 걸릴 수 있습니다. 시작에 실패하면 terminal error와 leader 연결을 확인하세요.

  1. 다음 단계를 위해 simulation을 계속 실행해 둡니다.

Camera Display 설정#

  1. Host browser에서 http://localhost:8090을 엽니다. Viewer에는 한 번에 browser tab 하나만 연결하세요.

  2. Camera feed만 보면서 vial을 집어 rack slot에 넣는 연습을 합니다.

  3. Browser에 focus를 두고 R을 눌러 environment를 reset합니다.

  4. 연습 중 terminal의 grasp 및 placement 상태를 확인합니다.

  5. Recording session을 시작하기 전에 terminal에서 Ctrl+C로 종료합니다.

Telemetry용으로 --browser-display 대신 --rerun을 사용할 수 있지만 두 flag는 함께 사용할 수 없습니다. Recording/reset keyboard control은 browser에서만 지원되며 Rerun, headless, Newton-only mode에서는 사용할 수 없습니다.

Demonstration 기록#

Dataset Visualizer에서 예시 dataset을 탐색하세요.

팁

Camera나 robot 연결 문제는 Troubleshooting Guide를 확인하세요.

Demonstration의 구성#

Episode는 전체 시도 또는 저장된 correction처럼 연속된 task sequence를 기록합니다. Wrist 및 external image, joint state, action, task instruction, timing을 함께 보관합니다. State는 robot이 있던 상태, action은 다음에 하도록 명령한 동작을 나타냅니다.

Dataset Namespace 설정#

Data를 수집할 준비가 되면 저장 위치를 지정하는 argument를 추가합니다.

  1. Dataset namespace를 설정합니다. Local 수집만 한다면 your-hf-username을 유지하고, upload할 계획이면 본인의 Hugging Face username으로 바꾸세요.

export HF_USER=your-hf-username

Terminal session마다 한 번만 설정하면 됩니다. Local 수집에는 Hugging Face login이 필요하지 않습니다.

Demonstration 기록 실행#

  1. Container에서 recording session을 시작합니다.

lerobot_agent --task Newton-So101-Teleop-Vials-To-Rack-DR-v0 --cameras all --browser-display presets=newton,ovrtx_renderer --repo_id "${HF_USER}/so101_teleop_vials_newton" --task_name "Pick up the vial and place it in the rack"

Recorder는 repo ID로 local 경로를 정합니다: datasets/<user>/so101_teleop_vials_newton.

참고

[ERROR]: Dataset root already exists가 나오면 --resume을 추가해 기존 dataset에 episode를 이어서 저장하세요. 별도 dataset을 만들려면 새로운 --repo_id를 선택합니다.

기존 dataset에 추가하려면 아래 명령을 실행합니다. 새 shell이라면 먼저 HF_USER를 다시 설정하세요.

lerobot_agent --task Newton-So101-Teleop-Vials-To-Rack-DR-v0 --cameras all --browser-display presets=newton,ovrtx_renderer --repo_id "${HF_USER}/so101_teleop_vials_newton" --task_name "Pick up the vial and place it in the rack" --resume

  1. http://localhost:8090을 엽니다. Viewer에는 browser tab 하나만 연결하세요.

  2. Browser에 focus를 두고 Space로 시작/저장, C로 폐기, R로 폐기 후 reset합니다.

  3. 원하는 demonstration 수를 모을 때까지 반복합니다.

  4. Browser의 saving 표시가 사라지고 terminal에 episode 저장 완료가 표시될 때까지 기다립니다. 완료된 episode는 background에서 저장됩니다. 예시:

[INFO]: Episode 1 saved.

  1. Terminal에서 Ctrl+C로 중단하고 shutdown이 끝날 때까지 기다립니다.

수집 Data 검토와 Upload#

  1. Dataset visualizer로 episode를 확인합니다.

lerobot-dataset-viz --repo-id "${HF_USER}/so101_teleop_vials_newton" --root "./datasets/${HF_USER}/so101_teleop_vials_newton" --episode-index 0

Visualizer가 Rerun에서 episode를 엽니다. 로드가 끝나면 Spacebar로 재생/일시 정지합니다. 원하는 만큼 반복 재생할 수 있습니다.

  1. --episode-index를 바꿔 여러 take를 검토하고 학습 전에 camera 할당과 placement 성공을 확인합니다.

Simulation recording 결과는 disk에 저장됩니다.

  1. 선택 사항: 공유하거나 Hub ID로 학습하려면 인증 후 완료된 dataset을 upload합니다.

hf auth login
export DATASET_ID="${HF_USER}/so101_teleop_vials_newton"
hf upload "$DATASET_ID" "./datasets/$DATASET_ID" . --repo-type dataset
hf repos tag create "$DATASET_ID" v3.0 --repo-type dataset --revision main
같은 Dataset에 Episode를 더 Upload하는 경우

hf upload 완료 후 기존 v3.0 tag를 교체해 갱신된 data를 가리키도록 합니다.

hf repos tag delete "$DATASET_ID" v3.0 --repo-type dataset
hf repos tag create "$DATASET_ID" v3.0 --repo-type dataset --revision main

v3.0은 이 workshop의 dataset format입니다. Tag에 관한 자세한 내용은 Hugging Face CLI guide를 참고하세요.

선택 사항: Automated Data Collection#

Workshop은 vial에 접근해 grasp하고 rack으로 옮긴 뒤 삽입·release하는 scripted controller인 vials_state_machine도 제공합니다. 전부 simulation에서 실행하므로 leader arm이나 학습된 policy가 필요 없으며, 같은 post-training workflow용 demonstration을 생성합니다.

Scripted Controller 미리 보기#

  1. Display port를 해제하도록 실행 중인 teleoperation 또는 evaluation client를 종료합니다.

  2. Workshop container에서 recording 없이 기본 state-machine task를 실행합니다.

vials_state_machine --task Newton-So101-Auto-Vials-State-Machine-v0 --cameras all --browser-display presets=newton,ovrtx_renderer

  1. http://localhost:8090을 열고 controller가 동작하는 동안 두 camera feed를 확인합니다. Viewer에는 tab 하나만 연결하세요.

  2. 수집 전에 Ctrl+C로 preview를 종료합니다.

성공한 Episode 기록#

  1. Recording을 활성화해 Domain Randomization task를 실행합니다. Local 수집만 한다면 your_hf_username을 유지하고, upload한다면 본인의 Hugging Face username을 사용하세요.

export HF_USER=your_hf_username
vials_state_machine --task Newton-So101-Auto-Vials-State-Machine-DR-v0 --record --num_episodes 5 --repo_id "${HF_USER}/so101_auto_vials_newton" --task_name "Pick up the vial and place it in the rack" --cameras all --browser-display presets=newton,ovrtx_renderer

목표는 5번 시도가 아니라 성공한 episode 5개입니다. Recorder는 성공한 episode만 받아들이고 실패한 시도는 버립니다. 두 camera가 모두 필요하며 recording은 자동입니다. Teleoperation의 Space/C control은 이 흐름에 사용하지 않습니다.

  1. 수집과 dataset export가 끝날 때까지 기다립니다. 실행 중 성공 episode를 임시 저장하고 목표 수를 채우면 LeRobot dataset으로 조립합니다. 중간에 멈추면 임시 episode만 남고 dataset은 완성되지 않을 수 있습니다.

  2. Upload 전에 export된 data를 확인합니다.

lerobot-dataset-viz --repo-id "${HF_USER}/so101_auto_vials_newton" --root "./datasets/${HF_USER}/so101_auto_vials_newton" --episode-index 0

  1. 선택 사항: 여러 episode의 camera coverage, grasp 품질, placement를 검토한 뒤 dataset을 upload합니다.

hf auth login
export DATASET_ID="${HF_USER}/so101_auto_vials_newton"
hf upload "$DATASET_ID" "./datasets/$DATASET_ID" . --repo-type dataset
hf repos tag create "$DATASET_ID" v3.0 --repo-type dataset --revision main

Simulation 사용:

  • DR로 초기 dataset을 구축할 때

  • Hardware가 부족하거나 공유 중일 때

  • Task 또는 policy variation을 빠르고 안전하게 탐색할 때

  • 실제 환경이 준비되지 않았거나 접근할 수 없거나 개발 중일 때

실제 Robot 사용:

  • 고품질 ground truth를 수집할 때

  • Simulation에서 학습한 policy를 검증할 때

  • Friction, lighting 등 실제 환경의 세부 특성을 기록할 때

Teleoperation과 자동 생성 Demonstration 혼합

Dataset을 혼합하면 수집 부담을 줄일 수 있습니다. Teleoperation은 사람이 task를 여러 번 반복해야 하므로 시간이 걸리지만(예시에서는 최대 75회), task generalization에 유용한 variation도 제공합니다.

자동 수집은 초기 pipeline 점검과 시험 또는 teleoperation 보완에 도움이 됩니다. 다만 적절히 randomize하지 않으면 model이 쉽게 overfit될 수 있습니다.

모든 task에 맞는 고정된 혼합 비율은 없습니다. 목적에 맞는 비율로 시작하고 teleoperation-only 또는 automation-only baseline과 비교한 뒤 부족한 조건의 예시를 추가하세요.

핵심 내용#

  • Teleoperation은 사람의 전문성을 demonstration으로 기록합니다.

  • Demonstration 수집 시에는 workspace를 직접 보지 말고 camera view만 사용하세요.
