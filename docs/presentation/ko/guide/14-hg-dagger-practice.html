HG-DAgger: Correction 수집#

Hands-on
이 Module에 필요한 준비물

실습입니다. 현재 Newton workshop container, calibration된 leader arm, policy checkpoint, NVIDIA GPU가 필요합니다. 실제 수집에는 calibration된 follower와 camera 두 대도 필요합니다.

Policy를 pause하고 leader로 correction을 수행한 뒤 학습용으로 저장합니다.

중요

Leader arm이 움직입니다. 실제 leader(teleop) arm은 시작, 정렬, reset, 정상 종료 중 motor 전원으로 움직입니다. Follower가 simulation이어도 같습니다. 이동 경로를 비우고 G 또는 L로 torque를 풀기 전에 leader를 받쳐 주세요.

학습 목표#

  • Leader를 정렬하고 correction을 수집한 뒤 policy에 제어권 반환

  • 사람이 돕는 수집과 자율 평가 비교

Workshop Container 준비#

Instructor가 준비한 container 또는 Get the Code에서 build한 image를 사용합니다.

  1. Arm이나 camera를 사용하는 teleoperation 및 evaluation session을 종료합니다.

  2. Workshop container terminal에서 계속합니다. 저장된 설정은 shell 시작 시 로드됩니다.

Leader의 TELEOP_PORT, TELEOP_ID와 실제 follower의 ROBOT_PORT, ROBOT_ID를 확인합니다. 실제 수집에서는 Camera Setup에 따라 CAMERA_GRIPPER, CAMERA_EXTERNAL을 확인하고 이 shell에서 camera configuration을 만듭니다.

export ROBOT_CAMERAS="{ wrist: {type: opencv, index_or_path: $CAMERA_GRIPPER, width: 640, height: 480, fps: 30, fourcc: MJPG}, external: {type: opencv, index_or_path: $CAMERA_EXTERNAL, width: 640, height: 480, fps: 30, fourcc: MJPG} }"

새 shell을 열면 export를 반복하세요. 아래 policy가 기대하는 wrist, external key를 사용합니다.

  1. 개선하려는 Co-Trained checkpoint를 선택합니다.

export MODEL_ID=sreetz-nv/so101_real10_sim75_vision_h16_b64_20k_20261011
export HF_USER=your_hf_username

예상되는 동작#

Simulation teleoperation 75개와 실제 demonstration 10개로 학습한 model이며 실제 시험에서 20 episode 중 10개(50%) 성공했습니다. Rack slot을 놓치는 placement를 관찰하고, pause한 뒤 correction을 수집하세요.

Local 수집만 하면 your_hf_username을 유지하고 upload할 계획이면 본인의 username으로 바꿉니다. Correction dataset은 upload 전까지 local에만 저장됩니다.

Rest Pose 지정#

  1. Leader를 bench 위의 rest pose에서 받쳐 줍니다.

  2. Leader calibration마다 한 번 실행합니다.

lerobot_dagger --teach-rest

  1. 실제 수집에서는 follower를 전원 직후처럼 접어 놓은 상태로 두고, follower calibration마다 한 번 실행합니다.

lerobot-rollout-dagger --robot.type=so101_follower --robot.port="$ROBOT_PORT" --robot.id="$ROBOT_ID" --robot.use_degrees=true --robot.disable_torque_on_disconnect=false --strategy.teach_follower_rest=true

두 명령은 arm을 움직이거나 torque를 풀지 않고 현재 위치만 저장합니다. 정상 종료 시 해당 위치로 돌아옵니다. Follower rest를 지정하기 전에는 시작할 때의 pose로 돌아갑니다.

중요

Leader는 시작, 정렬, reset, 정상 종료 중 전원으로 움직입니다. 경로를 비우세요. Torque를 푸는 G, L 전에 leader를 받쳐 줍니다. Gravity compensation은 없습니다. Robot safety 안내를 따르세요.

수집 시작#

실제 follower에는 lerobot-rollout-dagger를 실행합니다. LeRobot의 lerobot-rollout 안에서 policy를 직접 로드하므로 별도 policy server가 필요하지 않습니다.

export CORRECTION_ID="$HF_USER/so101_dagger_real_round1"
lerobot-rollout-dagger --policy.path="$MODEL_ID" --policy.base_model_path=nvidia/GR00T-N1.7-3B --policy.n_action_steps=16 --robot.type=so101_follower --robot.port="$ROBOT_PORT" --robot.id="$ROBOT_ID" --robot.use_degrees=true --robot.disable_torque_on_disconnect=false --robot.cameras="$ROBOT_CAMERAS" --strategy.repo_id="$CORRECTION_ID" --strategy.leader_port="$TELEOP_PORT" --strategy.leader_id="$TELEOP_ID" --device=cuda --start_pose_dataset=sreetz-nv/so101_sim_manual_perception_newton_20261008

이 실습의 starting pose는 merged dataset 전체가 아니라 Co-Training의 sim-teleoperation 75개에서 계산합니다. 시작하면 두 arm이 해당 dataset의 평균 시작 pose로 움직입니다. Policy 실행 전에 출력된 값을 확인하세요. 각 arm은 먼저 gripper를 열고 shoulder·elbow·wrist를 움직인 뒤 base와 wrist roll을 돌립니다. Gripper가 열리면 vial이 떨어지므로 시작/reset 전에 잡고 있는 vial을 제거하세요.

대신 Simulation에서 수집하기

현재 simulation 명령 lerobot_dagger는 --start_pose_dataset을 지원하지 않고 task 기본 pose를 사용합니다. 따라서 위 실제 명령과 시작 조건이 일치하는 비교가 아닙니다.

Simulation은 lerobot_dagger와 policy server를 사용합니다. 실제 follower 명령 대신 아래를 실행하세요. Leader는 여전히 실물이며 simulation follower를 제어합니다.

  1. 이 terminal의 background에서 전용 policy server를 시작합니다.

mkdir -p outputs
python -m lerobot.async_inference.policy_server --host=127.0.0.1 --port=8081 --fps=30 --inference_latency=0 > outputs/dagger-policy-server.log 2>&1 & DAGGER_SERVER_PID=$!
python -c "import grpc; grpc.channel_ready_future(grpc.insecure_channel('127.0.0.1:8081')).result(timeout=60); print('Policy server ready')"

Policy server ready를 기다립니다. Timeout이면 진행 전에 tail -n 40 outputs/dagger-policy-server.log를 확인하세요. 다른 client가 연결되면 state가 reset되므로 이 server는 DAgger 전용으로 유지합니다.

  1. 수집을 시작합니다.

export CORRECTION_ID="$HF_USER/so101_dagger_sim_round1"
lerobot_dagger --task Newton-So101-Teleop-Vials-To-Rack-Eval-v0 --cameras all --browser-display presets=newton,ovrtx_renderer --server_address 127.0.0.1:8081 --pretrained_name_or_path "$MODEL_ID" --port "$TELEOP_PORT" --robot_id "$TELEOP_ID" --repo_id "$CORRECTION_ID" --action_horizon 16 --seed 76000

  1. 완료하면 같은 shell에서 policy server를 종료합니다.

kill "$DAGGER_SERVER_PID"
wait "$DAGGER_SERVER_PID" || true
unset DAGGER_SERVER_PID

Simulation과 실제 correction은 별도 dataset에 저장하고 수집과 평가의 seed를 다르게 사용하세요.

http://localhost:8090을 엽니다. 시작 pose 정렬 후 paused 상태로 시작합니다. Keyboard control을 위해 page에 focus를 두고 viewer에는 tab 하나만 연결하세요.

정렬, Correction, 제어권 반환#

  1. Space로 policy를 실행하고 수정할 실패를 관찰합니다.

  2. Space를 다시 눌러 pause합니다. Follower는 마지막 명령을 유지하며 pause만으로 leader가 움직이지는 않습니다.

  3. Paused 상태에서 Tab을 누릅니다. Leader가 follower에 맞춰 움직이도록 두고 correction_ready를 기다리세요. 전원이 켜진 arm을 억지로 움직이지 마세요.

  4. Leader를 받친 뒤 G를 누릅니다. Torque가 풀리고 correction recording이 시작됩니다.

  5. Leader를 움직여 유용한 correction을 수행합니다. 예를 들어 grasp를 마치고 vial을 mat에서 들어 올립니다.

  6. Space로 leader를 고정하고 correction을 저장한 뒤 policy에 제어권을 돌려줍니다. Episode N saved로 저장을 확인하세요.

같은 rollout에서 필요에 따라 반복합니다.

Space → Space → Tab → wait → G → correct → Space

Key

기능

Space

Policy 시작/일시 정지. Correction 중에는 저장하고 policy 재개.

Paused 상태에서 Tab

Leader를 follower에 맞춰 이동. correction_ready 대기.

G

Leader torque 해제 후 correction 시작 또는 계속.

X

미완료 correction을 유지하며 정지·고정. G로 계속, Space로 저장.

C

미완료 correction 폐기 후 일시 정지.

R

미완료 correction을 폐기하고 arm을 시작 pose로 reset.

Esc / Ctrl+C (terminal)

종료 후 torque를 유지한 채 leader를 지정한 rest pose로 복귀.

L

Leader torque를 풀고 이동 없이 종료. 먼저 leader를 받쳐 주세요.

실제 robot은 R로 rollout을 끝내고 paused 상태에서 물체를 손으로 reset합니다. 자동 성공·timeout·safety reset이 없으므로 결과를 직접 기록하세요. Simulation에서는 성공, timeout, unsafe scene도 environment reset과 pause를 유발합니다.

Policy 제어 중 Leader를 Follower 가까이에 유지

실제 명령에 --strategy.leader_follows=true, simulation에는 --leader_follows를 추가합니다. 전원이 켜진 leader가 follower를 따라가 잦은 correction에 도움이 됩니다. 그래도 G 전에 pause하고 Tab을 누른 뒤 correction_ready를 기다려야 합니다. 추적 속도가 제한되어 leader가 늦을 수 있습니다.

검토와 종료#

종료 전에 Space로 유용한 correction을 저장하거나 C로 폐기하세요. 정상 종료 시 leader가 지정된 rest로 복귀합니다. 실제 hardware에서는 두 arm이 함께 시작 pose를 거쳐 각자의 rest로 이동하며 torque를 유지합니다. 전원을 끄기 전에 받쳐 주세요.

Container prompt에서 저장한 correction을 확인합니다.

lerobot-dataset-viz --repo-id "$CORRECTION_ID" --root "./datasets/$CORRECTION_ID" --episode-index 0

같은 dataset에 추가하려면 실제 명령에 --resume=true, simulation에 --resume을 추가합니다. 새 round는 CORRECTION_ID를 바꾸세요.

무엇이 기록될까?#

Session 구간

기록 여부

Policy rollout

아니요

Pause, alignment, reset

아니요

Leader로 수행한 human correction

저장하면 기록됨

저장한 correction 하나가 LeRobot episode 하나가 됩니다. 짧은 grasp, lift, placement도 충분하며 전체 task를 반복할 필요는 없습니다. 학습 전에 검토하고 simulation과 실제 correction은 별도 dataset으로 유지하세요.

갱신된 Policy 평가#

제공된 checkpoint로 correction 학습 효과를 시험합니다. GR00T 1.7 base에서 simulation demonstration 75개, 실제 10개, correction segment 29개로 학습했습니다. 방금 직접 수집한 correction은 이 checkpoint에 포함되지 않습니다.

  1. Correction session을 종료하고 두 arm이 rest로 돌아올 때까지 기다립니다.

  2. Correction을 학습한 model을 선택하고 검증한 camera 설정을 유지합니다.

export MODEL_ID=sreetz-nv/so101_real10_sim75_hgdagger29_vision_h16_b64_20k_20261013
export TASK_INSTRUCTION="Pick up the vial and place it in the rack"
export ROBOT_CAMERAS="{ wrist: {type: opencv, index_or_path: $CAMERA_GRIPPER, width: 640, height: 480, fps: 30, fourcc: MJPG}, external: {type: opencv, index_or_path: $CAMERA_EXTERNAL, width: 640, height: 480, fps: 30, fourcc: MJPG} }"

예상되는 동작#

Simulation teleoperation 75개, 실제 demonstration 10개, human correction segment 29개로 학습했습니다. 실제 시험은 20 episode 중 14개(70%) 성공했습니다. Slot 정렬과 placement의 변화를 보고 grasp와 lift도 여전히 잘 되는지 확인하세요.

위 수집 명령처럼 starting pose는 sim-teleoperation demonstration을 사용합니다. Correction은 task 중간부터 시작하므로 초기 frame을 전체 task 시작 pose로 쓸 수 없습니다. Policy action 전에 실제 pose를 simulation demonstration과 비교하세요.

선택 사항: 먼저 Simulation에서 시험

  1. 실제 rollout을 종료한 뒤 같은 container terminal을 사용합니다. MODEL_ID와 task instruction은 유지합니다.

  2. 아래 simulation policy server를 시작하거나 이미 실행 중이면 재사용합니다.

mkdir -p outputs
python -m lerobot.async_inference.policy_server --host=0.0.0.0 --port=8080 --fps=30 --inference_latency=0 > outputs/policy-server.log 2>&1 & POLICY_SERVER_PID=$!
python -c "import grpc; grpc.channel_ready_future(grpc.insecure_channel('localhost:8080')).result(timeout=60); print('Policy server ready')"

  1. Policy server ready를 기다린 뒤 평가를 실행합니다.

lerobot_eval --task Newton-So101-Teleop-Vials-To-Rack-DR-Eval-v0 --cameras all --browser-display presets=newton,ovrtx_renderer --server_address localhost:8080 --pretrained_name_or_path "$MODEL_ID" --policy_type groot --policy_device cuda --start_pose_dataset sreetz-nv/so101_sim_manual_perception_newton_20261008 --action_horizon 16 --num_episodes 10 --seed 76000 --lang_instruction "$TASK_INSTRUCTION"

  1. http://localhost:8090을 엽니다. Viewer에는 browser tab 하나만 연결하세요.

  2. 실제 policy를 실행하기 전에 background server를 종료합니다. 평가가 실행 중이면 먼저 Ctrl+C를 누르세요.

kill "$POLICY_SERVER_PID"
wait "$POLICY_SERVER_PID" || true
unset POLICY_SERVER_PID

또는 container의 모든 policy server를 종료합니다.

pkill -f '[l]erobot\.async_inference\.policy_server'

다른 terminal의 server를 재사용했다면 해당 terminal에서 종료합니다. 아래 실제 rollout은 policy를 직접 로드합니다.

  1. 개입 없이 실제 robot에서 correction 학습 policy를 실행합니다.

lerobot-rollout --strategy.type=workshop --policy.path="$MODEL_ID" --policy.base_model_path=nvidia/GR00T-N1.7-3B --policy.n_action_steps=16 --robot.type=so101_follower --robot.port="$ROBOT_PORT" --robot.id="$ROBOT_ID" --robot.use_degrees=true --robot.cameras="$ROBOT_CAMERAS" --task="$TASK_INSTRUCTION" --device=cuda --display_data=true --inference.type=rtc --inference.rtc.enabled=false --inference.rtc.execution_horizon=16 --inference.queue_threshold=0 --start_pose_dataset=sreetz-nv/so101_sim_manual_perception_newton_20261008

Rollout Control

시작 시 arm이 workshop 시작 pose로 움직인 뒤 P를 기다립니다. Rollout terminal에 focus를 두세요. Key는 대소문자를 구분하지 않습니다.

Key

동작

P

P for policy: 첫 trial 또는 다음 trial을 시작합니다.

S / F

성공/실패를 기록하고 시작 pose로 복귀한 뒤 일시 정지합니다.

N / →

N for next: Trial을 폐기하고 시작 pose로 복귀한 뒤 일시 정지합니다.

Q / Esc

Q for Quit: 종료하며 미완료 trial은 폐기합니다.

Ctrl+C

Rollout을 중단하고 cleanup을 실행합니다.

소품을 옮기기 전에 Paused를 기다리세요. 종료할 때도 cleanup과 복귀 동작이 끝난 뒤 arm을 만집니다.

Model 비교 시 terminal에 표시되는 첫 action 지연과 평가한 trial 중 성공 수를 기록하세요.

  1. 같은 시작 조건에서 원래 Co-Trained policy와 비교하세요. Vial이 여전히 slot을 놓치나요? Placement 개선과 함께 grasp, lift, 복귀도 유지되는지 확인합니다. 성공과 실패를 기록하고 위 workshop 결과와 비교하세요.

핵심 내용#

  • Policy에 도움이 필요한 곳에서 correction을 수집합니다.

  • Fine-tuning 전에 correction과 호환되는 demonstration을 혼합합니다.

  • 갱신된 policy는 사람의 도움 없이 시험합니다.
