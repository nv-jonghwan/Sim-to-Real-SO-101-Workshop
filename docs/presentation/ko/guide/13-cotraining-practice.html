Co-Training 실습#

Hands-on
이 Module에 필요한 준비물

실습입니다. Calibration된 SO-101 robot과 leader arm, camera 두 대, 조립된 workspace, so101-workshop container가 필요합니다.

실제 robot에서 Co-Trained policy와 sim-only baseline을 비교합니다.

학습 목표#

이 session을 마치면 다음을 수행할 수 있습니다.

  • 학습한 policy를 실제 SO-101에 안전하게 배포

  • 실제 policy 동작 관찰과 기록

  • 초기 Sim-to-Real gap 증상 파악

결과 예시#

이 실제 robot session은 simulation teleoperation demonstration 75개와 실제 demonstration 10개로 학습한 policy를 보여줍니다. 아래 실습은 Sim75 + Real10 checkpoint를 사용합니다.

가장 흔한 rack의 vial slot을 놓치는 실패를 주의 깊게 보세요. 본인 setup에서도 같은 문제가 나타나는지 비교하세요.

이 소규모 시험에서는 robot 색상과 vial을 조금 바꾸어도 policy 성능에 측정 가능한 영향이 없었습니다.

선택 사항: LeRobot으로 실제 Demonstration 수집#

이미 준비되어 있습니다: 행사 dataset과 학습 model이 제공되므로 이 실습에서 수집, merge, upload, 학습할 필요는 없습니다. Deploy a Co-Trained Policy로 진행하세요. 아래 dropdown은 나중에 준비 workflow를 직접 해보기 위한 참고입니다.

참고

Simulation과 실제 demonstration에서 camera 이름, joint 순서, normalization, frame rate, task instruction을 같게 사용합니다.

참고: 직접 Co-Training Data 수집과 준비

이 workflow는 새 실제 episode 5개부터 수집합니다. 선택된 checkpoint의 training dataset과는 별도의 수집입니다.

  1. 실행 중인 rollout을 끝낸 뒤 기존 container terminal을 사용합니다.

  2. Upload할 계획이면 hf auth login으로 로그인하세요. Local 수집만 한다면 생략합니다(권장).

  3. Dataset namespace를 설정합니다. Local 수집은 placeholder를 유지하고, upload하려면 본인의 Hugging Face username을 사용하세요.

export HF_USER=your-hf-username

  1. dataset.repo_id를 반드시 설정한 뒤 아래 명령을 실행합니다.

lerobot-record --robot.type=so101_follower --robot.port=$ROBOT_PORT --robot.id=$ROBOT_ID --robot.cameras='{ "wrist": { "type": "opencv", "index_or_path": '"$CAMERA_GRIPPER"', "width": 640, "height": 480, "fps": 30 }, "external": { "type": "opencv", "index_or_path": '"$CAMERA_EXTERNAL"', "width": 640, "height": 480, "fps": 30 } }' --teleop.type=so101_leader --teleop.port=$TELEOP_PORT --teleop.id=$TELEOP_ID --display_data=true --dataset.repo_id=${HF_USER}/so101-teleop-vials-to-rack-real --dataset.root="./datasets/${HF_USER}/so101-teleop-vials-to-rack-real" --dataset.push_to_hub=false --dataset.num_episodes=5 --dataset.single_task="Pick up the vial and place it in the rack" --play_sounds=false

  1. Recording control은 다음과 같습니다.

  • Right Arrow (→): 현재 episode 또는 reset 시간을 조기에 끝내고 다음으로 이동합니다.

  • Left Arrow (←): 현재 episode를 취소하고 다시 기록합니다.

  • Escape (ESC): Session을 끝내고 video encoding과 저장 완료를 기다립니다.

자세한 내용은 lerobot-record를 참고하세요.

  1. 완료된 dataset을 upload하고 tag를 지정합니다.

export DATASET_ID="${HF_USER}/so101-teleop-vials-to-rack-real"
hf upload "$DATASET_ID" "./datasets/$DATASET_ID" . --repo-type dataset
hf repos tag create "$DATASET_ID" v3.0 --repo-type dataset --revision main

같은 dataset에 나중에 다시 upload할 때는 tag를 갱신하세요.

  1. Teleoperating in Sim의 local simulation dataset과 방금 기록한 실제 episode를 merge합니다.

export SIM_DATASET_ID="${HF_USER}/so101_teleop_vials_newton"
export REAL_DATASET_ID="${HF_USER}/so101-teleop-vials-to-rack-real"
export DATASET_NAME=so101_vials_sim_real_round1
export MERGED_DATASET_ID="${HF_USER}/${DATASET_NAME}"
lerobot-edit-dataset --new_repo_id "$MERGED_DATASET_ID" --new_root "./datasets/$MERGED_DATASET_ID" --operation.type merge --operation.repo_ids "['$SIM_DATASET_ID', '$REAL_DATASET_ID']" --operation.roots "['./datasets/$SIM_DATASET_ID', './datasets/$REAL_DATASET_ID']" --push_to_hub=false

두 입력 folder는 완성된 LeRobot dataset이어야 합니다. 자동 수집을 했다면 merge 전에 SIM_DATASET_ID를 ${HF_USER}/so101_auto_vials_newton으로 설정하세요. Merge마다 새 output 이름을 사용하고 camera 이름(wrist, external), joint 단위, task instruction, 30 Hz frame rate가 일치하는지 확인합니다.

두 source의 모든 episode를 balancing이나 복제 없이 포함합니다. 긴 dataset이 더 많은 training frame을 제공하므로, merge만으로 50/50 sampling ratio가 만들어지거나 Sim75 + Real10 model이 재현되지는 않습니다.

  1. Merge된 dataset에서 두 source의 episode를 확인합니다. Simulation episode가 먼저, 실제 episode가 뒤에 옵니다.

lerobot-dataset-viz --repo-id "$MERGED_DATASET_ID" --root "./datasets/$MERGED_DATASET_ID" --episode-index 0

--episode-index를 바꿔 실제 episode도 확인하세요. 첫 실제 index는 입력 simulation episode 수와 같습니다. 이후 merged dataset을 upload합니다.

hf upload "$MERGED_DATASET_ID" "./datasets/$MERGED_DATASET_ID" . --repo-type dataset
hf repos tag create "$MERGED_DATASET_ID" v3.0 --repo-type dataset --revision main

  1. GR00T Post-Training을 따르되 DATASET_NAME=so101_vials_sim_real_round1을 사용합니다. 이름을 선택한 뒤 training variable을 정의해 dataset, model ID, output directory가 새 실험을 가리키게 하세요.

실습: Co-Trained Policy 배포#

Sim75 + Real10 policy는 simulation teleoperation episode 75개와 실제 demonstration 10개로 20,000 update를 학습한 GR00T 1.7 checkpoint입니다. 16-action window, vision trainable, language frozen을 사용합니다. Video는 예비 실제 시험이며, 이번 실습에서 본인 station의 성능을 측정합니다.

Model download와 benchmark 조건을 확인하세요.

Workspace 준비#

진행 전에 Safety를 확인하세요.

  1. Follower 연결과 calibration한 robot ID를 확인합니다.

  2. Sim-only baseline에 사용한 workspace에 vial과 rack을 배치합니다.

  3. Camera 할당과 가림 여부를 확인합니다.

  4. Baseline과 같은 설정으로 lightbox 조명을 켭니다.

실행과 비교#

  1. 이전 rollout을 끝내고 Real Evaluation에 따라 같은 container terminal을 사용합니다.

  2. 선택한 Co-Trained model 또는 download 안내의 local 경로를 설정합니다.

export MODEL_ID=sreetz-nv/so101_real10_sim75_vision_h16_b64_20k_20261011
export TASK_INSTRUCTION="Pick up the vial and place it in the rack"
export ROBOT_CAMERAS="{ wrist: {type: opencv, index_or_path: $CAMERA_GRIPPER, width: 640, height: 480, fps: 30, fourcc: MJPG}, external: {type: opencv, index_or_path: $CAMERA_EXTERNAL, width: 640, height: 480, fps: 30, fourcc: MJPG} }"

  • Sim teleop ✓ Used
  • Real data ✓ Used

16-action window · Vision trainable · Language frozen · Training details ↗

예상되는 동작#

Simulation teleoperation demonstration 75개와 실제 demonstration 10개로 학습했습니다. 실제 시험에서 20 episode 중 10개(50%) 성공했습니다. Sim-only policy와 grasp 및 placement를 비교하고, vial tip이 rack slot을 놓치는지 특히 살펴보세요.

Real Evaluation의 camera 구성과 wrist, external key를 사용합니다.

아래 두 명령은 merged training dataset의 실제 10개와 simulation 75개 episode로 starting pose를 계산합니다.

선택 사항: 먼저 Simulation에서 시험

  1. 실제 rollout을 종료한 뒤 같은 container terminal을 사용합니다. MODEL_ID와 task instruction은 유지합니다.

  2. 아래 simulation policy server를 시작하거나 이미 실행 중이면 재사용합니다.

mkdir -p outputs
python -m lerobot.async_inference.policy_server --host=0.0.0.0 --port=8080 --fps=30 --inference_latency=0 > outputs/policy-server.log 2>&1 & POLICY_SERVER_PID=$!
python -c "import grpc; grpc.channel_ready_future(grpc.insecure_channel('localhost:8080')).result(timeout=60); print('Policy server ready')"

  1. Policy server ready를 기다린 뒤 평가를 실행합니다.

lerobot_eval --task Newton-So101-Teleop-Vials-To-Rack-DR-Eval-v0 --cameras all --browser-display presets=newton,ovrtx_renderer --server_address localhost:8080 --pretrained_name_or_path "$MODEL_ID" --policy_type groot --policy_device cuda --start_pose_dataset sreetz-nv/so101_real10_sim75_20261011 --action_horizon 16 --num_episodes 10 --seed 76000 --lang_instruction "$TASK_INSTRUCTION"

  1. http://localhost:8090을 엽니다. Viewer에는 browser tab 하나만 연결하세요.

  2. 실제 policy를 실행하기 전에 background server를 종료합니다. 평가가 실행 중이면 먼저 Ctrl+C를 누르세요.

kill "$POLICY_SERVER_PID"
wait "$POLICY_SERVER_PID" || true
unset POLICY_SERVER_PID

또는 container의 모든 policy server를 종료합니다.

pkill -f '[l]erobot\.async_inference\.policy_server'

다른 terminal의 server를 재사용했다면 해당 terminal에서 종료합니다. 아래 실제 rollout은 policy를 직접 로드합니다.

  1. 실제 robot에서 policy를 실행합니다.

lerobot-rollout --strategy.type=workshop --policy.path="$MODEL_ID" --policy.base_model_path=nvidia/GR00T-N1.7-3B --policy.n_action_steps=16 --robot.type=so101_follower --robot.port="$ROBOT_PORT" --robot.id="$ROBOT_ID" --robot.use_degrees=true --robot.cameras="$ROBOT_CAMERAS" --task="$TASK_INSTRUCTION" --device=cuda --display_data=true --inference.type=rtc --inference.rtc.enabled=false --inference.rtc.execution_horizon=16 --inference.queue_threshold=0 --start_pose_dataset=sreetz-nv/so101_real10_sim75_20261011

Rollout Control

시작 시 arm이 workshop 시작 pose로 움직인 뒤 P를 기다립니다. Rollout terminal에 focus를 두세요. Key는 대소문자를 구분하지 않습니다.

Key

동작

P

P for policy: 첫 trial 또는 다음 trial을 시작합니다.

S / F

성공/실패를 기록하고 시작 pose로 복귀한 뒤 일시 정지합니다.

N / →

N for next: Trial을 폐기하고 시작 pose로 복귀한 뒤 일시 정지합니다.

Q / Esc

Q for Quit: 종료하며 미완료 trial은 폐기합니다.

Ctrl+C

Rollout을 중단하고 cleanup을 실행합니다.

소품을 옮기기 전에 Paused를 기다리세요. 종료할 때도 cleanup과 복귀 동작이 끝난 뒤 arm을 만집니다.

Model 비교 시 terminal에 표시되는 첫 action 지연과 평가한 trial 중 성공 수를 기록하세요.

  1. 비교 가능한 trial에서 grasp/placement 성공, recovery 시도, 낙하, overshoot를 기록합니다.

  2. Trial을 채점하거나 폐기하고 Paused를 기다린 뒤 소품을 reset합니다. P로 재시도하거나 checkpoint 변경 전에 Q / Esc로 종료하세요.

선택 사항: State-Machine Variation을 추가한 i5

  1. 이전 rollout을 종료하고 cleanup 후 다음 model을 선택합니다.

export MODEL_ID=liorbenhorin-nv/so101_vision_dr_i5_GR00T17_20261013
export TASK_INSTRUCTION="Pick up the vial and place it in the rack"
export ROBOT_CAMERAS="{ wrist: {type: opencv, index_or_path: $CAMERA_GRIPPER, width: 640, height: 480, fps: 30, fourcc: MJPG}, external: {type: opencv, index_or_path: $CAMERA_EXTERNAL, width: 640, height: 480, fps: 30, fourcc: MJPG} }"

i5 · Co-training + state-machine variation

Co-training followed by broader simulated layouts

🤗 Hugging Face ↗

210 episodes across two stages75 sim teleop + 10 real → 125 state-machine sim

  • State machine ✓ Used
  • Sim teleop ✓ Used
  • Real data ✓ Used

20,000 + 5,000 updates · Batch 32 · Final 16-action training window
Vision trainable · Language frozen · Training details ↗

Training data: Stage 1: 75 sim ↗ · Stage 1: 10 real ↗ · Stage 2: 125 state-machine demos ↗

What to Expect

처음에는 sim-teleoperation 75개와 실제 demonstration 10개로 학습하고, 이후 더 넓은 rack 배치의 state-machine demonstration 125개로 추가 학습했습니다. 실제 시험은 20회 중 9회(45%) 성공했습니다. Workspace 반대쪽 rack 배치도 일부 지원합니다. 해당 배치에서 grasp와 slot 정렬을 평소 setup과 비교하세요.

Model의 두 번째 학습 단계에 사용된 state-machine dataset의 초기 pose를 사용합니다. P 전에 실제 시작 pose를 확인하세요.

핵심 내용#

  • Co-Training은 simulation과 실제 data를 결합해 policy 개선을 시도합니다.

  • 관찰 결과를 체계적으로 기록하면 개선 방향을 정할 수 있습니다.

  • Sim-to-Real gap은 실제로 존재하며 큰 경우가 많습니다.

  • Policy마다 실패 양상이 다릅니다.
