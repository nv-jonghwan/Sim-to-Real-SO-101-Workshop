Update 한 번에 사용하는 data는 얼마나 될까요?

GPU 1개: 32 windows × 16 action targets = optimizer update당 512 target timesteps입니다.

중복 sample을 포함한 예시 계산이며 고유 episode 수를 뜻하지 않습니다. Mask 처리되지 않은 유효한 target만 loss에 기여합니다. 이 control을 조작해도 workshop recipe는 바뀌지 않습니다. Effective batch = batch size per GPU × GPU processes입니다.

단계나 객체를 선택하면 설명을 볼 수 있습니다.

Batch size

Batch size는 episode 전체가 아니라 sampling한 observation/action window의 수입니다. 각 window에는 camera 이미지, instruction, joint state와 sampling한 frame부터 시작하는 action target chunk가 포함됩니다. 이 과정의 고정된 training loop에서는 batch size × GPU processes가 optimizer update 한 번의 effective batch입니다. 각 GPU가 자신의 batch를 처리하고 gradient를 동기화한 뒤 optimizer가 한 번 update합니다. 이 loop는 여러 batch를 누적한 뒤 update하는 방식이 아닙니다.

Training horizon

Training action horizon은 observation 하나에 대응하는 action target 수입니다. Target은 해당 frame부터 시작하며 index는 0부터 H−1까지입니다. 30 Hz에서 16개 command는 약 0.53초의 제어에 해당하며, 첫 target과 마지막 target의 timestamp 차이는 0.50초입니다. Chunk가 길어지면 학습할 시간적 관계가 달라지고 target 크기가 커집니다. Loader는 요청한 chunk를 base model이 지원하는 horizon 이내로 제한합니다. 지원되는 training horizon을 사용하세요. 이는 rollout에서 실행하는 action 수와 별개입니다. Arm target은 observation state에 대한 상대값이고 gripper는 절대값을 유지합니다. Image augmentation은 선택 사항입니다.

Trainable components

이미지, instruction, joint state가 model의 조건이 됩니다. Flow matching은 sampling한 flow time에서 action target과 random noise를 섞습니다. Action head는 target flow(action minus noise)를 예측하고, masked mean-squared error로 training loss를 계산합니다. Backpropagation은 학습 대상 weight의 gradient를 계산합니다. Freeze된 component도 feature를 제공하지만 optimizer update를 받지는 않습니다. Vision을 unfreeze하면 학습 대상 weight가 늘어나며 일반적으로 memory 사용량도 증가합니다.

Learning rate

Backpropagation 후 설정에 따라 gradient norm을 clipping한 뒤, optimizer가 학습 대상 weight를 갱신합니다. Learning rate는 optimizer와 함께 update의 크기를 조절합니다. Schedule에 따라 update가 진행되는 동안 learning rate가 변합니다. 이후 loop는 gradient를 초기화하고 learning-rate schedule을 다음 단계로 진행합니다. 이 optimizer update 한 번이 training step 하나입니다. 설정한 step 수만큼 반복한 뒤 저장된 policy를 평가합니다.
