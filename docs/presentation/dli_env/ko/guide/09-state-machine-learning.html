실제 Demonstration으로 State Machine 만들기#

Lecture

State machine은 대규모 demonstration data를 생성하고 physics configuration을 조정해 Sim-to-Real gap을 줄이는 데도 활용할 수 있습니다. Task를 여러 phase와 phase 간 전환 규칙으로 나눕니다.

직접 만들려면 motion 분석과 정교한 programming이 필요하며, 움직임의 “DNA”를 포착하기가 어렵습니다. Coding agent는 소수의 human demonstration에서 세부 동작과 패턴을 분석하고 state machine을 작성한 뒤 예시와 비교해 개선할 수 있습니다. 여기서는 실제 data로 simulation을 만들고 조정하는 과정을 real-to-sim이라고 부릅니다.

학습 목표#

  • 실제 demonstration으로 state machine을 설계하는 방법 설명

  • Human demonstration과 생성된 demonstration의 trajectory 세부 동작과 timing 비교

  • 더 큰 dataset 수집 전에 agent가 필요한 수정을 하도록 안내

소수의 Demonstration에서 새로운 Layout으로#

예시로, 각 episode를 직접 teleoperate하지 않고 새로운 vial 및 rack 배치의 simulation demonstration을 state machine으로 수집합니다.

이렇게 생성한 새로운 배치의 data로 기존 policy를 fine-tune합니다. 실험에서는 simulation에만 존재했던 배치에서도 실제 rollout이 성공하는 사례를 확인했습니다.

범위를 명확히 한 Prompt로 시작#

sreetz-nv/so101_real_manual의 실제 demonstration 10개로 시작합니다. Agent가 비교 결과를 좋게 보이려고 scene을 바꾸지 않도록, prompt는 motion에 집중시킵니다.

Prompt 예시: State Machine 작성과 개선
Review these 10 real demonstrations of our task:
https://huggingface.co/datasets/sreetz-nv/so101_real_manual

Analyze them closely and build a state machine that matches their motion
characteristics.

Keep the existing geometry, shapes, colors, camera parameters, lighting,
materials, and render settings unchanged. These are already established
in our code.

Focus on robot commands: trajectories, linear and angular velocities,
smoothness, natural variation, grasp positions, and the approach, grasp,
lift, insertion, and retraction strategies. Build a state machine that
can generate reliable demonstrations at a larger scale than these
10 examples.

Compare the resulting motions in the camera observations against the
real demonstrations. Check framing, how much of the image each object
occupies, and the timing of each movement. Review, compare, and refine.

Motion을 분석한 뒤 개선#

Task 완료 여부만 보지 말고 단계의 순서, gripper 경로, 진행 중 속도 변화를 비교하세요.

실험에서 배운 점#

Procedural 방식으로 접근#

Agent는 예시를 단순 재생하는 “motion bank”를 만들 수 있습니다. Motion을 작은 단위로 나누어 서로 다른 배치에서도 procedural하게 생성하도록 안내합니다.

Starting-Pose Distribution 맞추기#

Vial과 rack 위치를 바꾸더라도 state machine이 항상 같은 pose에서 시작하면 training distribution이 좁아집니다. Domain Randomization으로 매번 camera view가 달라지면 같은 시작 pose도 다르게 보여 놓치기 쉽습니다.

Grasp Height 확인#

Jaw가 vial을 잡는 높이에 따라 wrist image 속 vial 위치가 달라집니다. Simulation에서 grasp에 성공해도 실제 demonstration과 다르게 보일 수 있습니다. 두 view에서 cap, vial body, jaw를 비교하고 실제 material과의 contact가 grasp에 미치는 영향도 고려하세요.

Pickup Timing 맞추기#

Gripper를 닫은 뒤의 멈춤도 training data에 포함됩니다. 생성된 demonstration이 lift 전에 반복해서 머뭇거리면 policy도 이를 학습할 수 있습니다. 멈춘 동안 observation 변화가 작으면 lift 시작 시점을 판단하지 못하고 정지 action을 계속 예측할 수 있습니다. Lift의 종료 위치뿐 아니라 시작 시점도 비교하세요.

Demonstration 확장의 또 다른 방법: Isaac AutoData#

Isaac AutoData는 annotation이 있는 소수의 seed demonstration을 simulation에서 대규모 demonstration으로 확장합니다. 예시를 object 기준 motion segment로 나누고 새로운 object 배치와 scene에 맞게 조정한 뒤, 이어 붙여 실행하고 성공한 demonstration을 저장합니다. 여기서 사용한 방법은 coding agent가 state machine을 작성하고 개선하는 방식이며, AutoData는 시연한 motion 자체를 변환하고 재조합합니다. 두 방법 모두 manual 수집을 줄이며, AutoData는 seed example에서 variation을 생성하는 체계적인 방법을 제공합니다. 자세한 내용은 AutoData documentation을 참고하세요.

Demonstration 확장의 또 다른 방법: Agent를 Policy로 사용#

Coding agent가 simulation robot을 직접 제어하는 policy 역할을 맡을 수도 있습니다. Camera image와 joint reading을 입력받고 joint target을 반환합니다.

작성하거나 debugging할 state machine은 없습니다. 다만 inference time이 병목입니다. 결정할 때마다 remote model을 blocking 호출하며, 실험에서는 chunk마다 추론에 수 초가 걸릴 수 있었습니다. 그동안 simulation이 멈추므로 motion은 simulated time으로 진행되고 수집은 state machine보다 훨씬 느립니다.

State machine과 같은 기준으로 rollout을 검토하세요. 대규모 수집 전에 시작 pose, grasp height, lift 시작 시점을 확인합니다.

핵심 내용#

  • Timing을 확인하세요. Grasp와 placement에 필요한 멈춤은 유지하되 의도하지 않은 지연과 머뭇거림은 제거합니다.

  • Motion과 contact를 살펴보세요. Joint configuration, grasp 위치, 실제 material과의 상호작용을 확인합니다.

  • 결과뿐 아니라 경향도 비교하세요. 작은 pose와 timing 차이가 trajectory 전체에서 누적될 수 있습니다.

  • Agent로 검토·비교·개선하세요. 수집 규모를 늘리기 전에 생성된 demonstration을 확인하고, 학습한 policy를 simulation과 실제 환경에서 모두 평가합니다.
