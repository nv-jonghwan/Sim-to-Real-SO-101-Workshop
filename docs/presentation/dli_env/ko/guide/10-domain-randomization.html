Lecture

학습 목표#

이 session을 마치면 다음을 수행할 수 있습니다.

  • Domain Randomization과 Sim-to-Real transfer를 개선하는 이유 설명

  • Demonstration 증강에 Domain Randomization 적용

Domain Randomization이란?#

Domain Randomization (DR)은 simulation을 실제 환경과 완벽하게 일치시키는 대신, 학습 중 simulation parameter를 변화시켜 실제 값을 포함한 range 전체에서 policy가 견고하게 동작하도록 하는 Sim-to-Real 전략입니다.

공 잡기를 배우는 상황을 생각해 보세요.

항상 같은 pose에서 공을 잡으면 팔을 뻗어 잡거나 glove 방향을 바꾸는 법을 배우지 못할 수 있습니다. 연습할 때 공이 날아오는 위치를 다양하게 하면 더 좋은 공 잡기 “policy”를 배울 수 있습니다.

무엇을 Randomize할까?

유용한 기준은 scene에서 바뀔 것으로 예상되는 요소의 parameter를 변화시키는 것입니다. Object mass와 scale, position, orientation을 고려하세요.

Robot을 foamcore에 고정하면 base가 기울어질 수 있어 base tilt를 −3°에서 +6°까지 randomize합니다. Mount 차이를 반영하기 위해 external camera tilt도 기준 각도에서 ±5° 변화시킵니다.

아래는 가능한 randomization 범주입니다. 현재 SO-101 task에서 실제로 켜진 항목은 아래 code tour에서 구분합니다.

Visual Domain Randomization:

  • Object color, texture, material

  • 조명의 intensity, direction, color temperature

  • Camera position, orientation, field of view

  • Background 외관

Physics와 actuation도 randomize할 수 있습니다.

Physics Domain Randomization:

  • Object mass, friction, restitution

  • Joint damping, friction, limit

  • Actuator delay, noise, offset

  • Sensor noise 특성

장점과 한계

장점:

  • 증강에 실제 data가 필요하지 않습니다.

  • 알 수 없는 parameter에 대응합니다.

  • 많은 parameter로 확장할 수 있습니다.

  • 구현이 간단합니다.

한계:

  • Range 조정에 경험적 판단이 많이 필요합니다.

  • 최적 성능과 robustness 사이의 절충이 있습니다.

  • 보수적이고 느린 motion을 만들 수 있습니다.

  • 매우 dynamic한 task에는 잘 맞지 않을 수 있습니다.

Simulation의 Domain Randomization#

Randomization은 environment reset 시 실행됩니다. Take 저장만으로는 reset되지 않습니다. 새로운 배치를 만들려면 R을 누르세요.

현재 checkout의 설정입니다. Camera position, robot color, physics randomization을 바꾸려면 명시적으로 설정을 수정해야 합니다. DR task라는 이름만으로 가능한 모든 randomization이 켜지는 것은 아닙니다.

Reset event는 Isaac Lab의 EventTerm API를 사용합니다. 예시:

1reset_lightbox_light_exposure = EventTerm(
2    func=mdp.randomize_light_exposure,
3    mode="reset",
4    params={
5        "exposure_range": (1.0, 3.0),
6        "asset_cfg": SceneEntityCfg("lightbox_light"),
7    },
8)

구현은 source/sim_to_real_so101/mdp/resets.py에 있습니다. ovrtx는 scene을 따로 로드하므로 시각적 변경을 workshop의 attribute 또는 asset-path write helper로 renderer에 전달해야 합니다. Live USD stage만 수정하면 rendered image가 바뀌지 않습니다. 전체 scene reset에서 global HDRI를 바꾸며, texture 로드를 위해 몇 frame의 warmup을 허용하세요.

Mount된 source/에서 event parameter를 수정하고 simulation을 재시작해 두 camera feed를 확인하세요. 기존 dataset과 policy를 사용할 때는 joint 순서, normalization, camera calibration을 유지합니다.

핵심 내용#

  • Domain Randomization은 다양한 조건에서 학습해 policy를 견고하게 만듭니다.

  • DR 증강은 여러 조건의 예시로 dataset을 확장합니다.

  • 실제 demonstration과 DR 증강의 조합은 강력한 baseline입니다.
