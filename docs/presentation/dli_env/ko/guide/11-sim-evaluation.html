Simulation 평가#

Hands-on
이 Module에 필요한 준비물

실습입니다. 실행 중인 so101-workshop container, NVIDIA RTX GPU, 호환되는 LeRobot GR00T 1.7 checkpoint가 필요합니다.

실제 robot에 배포하기 전에 Newton physics와 ovrtx camera를 사용하는 Isaac Lab 3.0에서 policy를 평가합니다.

학습 목표#

  • Workshop container의 terminal 하나에서 simulation 평가 실행

  • 기본 조건과 Domain Randomization 평가 조건 비교

  • Grasp, placement, 실패 양상 기록

중요

Simulation 성공이 실제 성공을 보장하지는 않습니다. 높은 simulation 점수는 유용한 출발점이지만 더 좋은 실제 policy를 의미하지는 않습니다. 같은 checkpoint를 실제 robot에서도 시험하고 두 결과를 별도로 기록하세요.

Trial 전에 선택한 checkpoint의 training data와 시작 조건을 비교하세요. Evaluation task의 기본 reset이 dataset의 시작 조건과 같다고 가정해서는 안 됩니다.

Policy 평가 실행#

  1. 기존 so101-workshop container terminal을 사용합니다. 실행 중인 실습을 Ctrl+C로 끝내고 prompt를 기다립니다.

Workshop Container 시작

Container가 꺼져 있다면 host terminal에서 다음을 실행합니다.

cd ~/Sim-to-Real-SO-101-Workshop

위 cd 명령에는 실제 저장소 경로를 사용하세요. ~/Sim-to-Real-SO-101-Workshop는 예시입니다. 같은 터미널에서 현재 폴더에 docker/Dockerfile과 source/가 있는지 확인한 뒤 다음 명령 블록을 실행하세요.

xhost +
docker run --name so101-workshop -it --rm --privileged --runtime=nvidia --network=host -e DISPLAY -v /tmp/.X11-unix:/tmp/.X11-unix -v ~/.Xauthority:/root/.Xauthority -v /dev:/dev -v /run/udev:/run/udev:ro -v ~/.cache/huggingface:/root/.cache/huggingface -v ~/.cache/ovrtx:/root/.cache/ovrtx -v ~/.cache/warp:/root/.cache/warp -v ./docker/env:/root/env -v ./source:/workspace/Sim-to-Real-SO-101-Workshop/source -v ./outputs:/workspace/Sim-to-Real-SO-101-Workshop/outputs -v ./datasets:/workspace/Sim-to-Real-SO-101-Workshop/datasets -v ./models:/workspace/Sim-to-Real-SO-101-Workshop/models so101-workshop:latest

현재 lerobot_eval은 policy server에 연결합니다. Policy마다 이 shell의 background에서 새 server를 시작해 평가용 prompt를 남겨 둡니다.

중요

Policy를 바꾸기 전에 server를 종료하세요. 평가를 마칠 때마다 다음 policy를 시작하기 전에 아래 server 종료 방법 중 하나를 사용합니다. 같은 shell에서 kill, wait, unset을 실행하거나 container 안의 모든 policy server를 종료합니다.

mkdir -p outputs
python -m lerobot.async_inference.policy_server --host=0.0.0.0 --port=8080 --fps=30 --inference_latency=0 > outputs/policy-server.log 2>&1 & POLICY_SERVER_PID=$!
python -c "import grpc; grpc.channel_ready_future(grpc.insecure_channel('localhost:8080')).result(timeout=60); print('Policy server ready')"

Policy server ready를 기다린 뒤 진행합니다. Timeout이 나면 tail -n 40 outputs/policy-server.log를 확인해 오류를 해결하세요. Log는 mount된 outputs/에 남습니다. 정리를 위해 이 shell의 POLICY_SERVER_PID를 유지하고, 기존 server가 실행 중일 때 다른 server를 시작하지 마세요.

  1. 같은 prompt에서 model repository 또는 local checkpoint directory를 설정합니다.

export MODEL_ID=sreetz-nv/so101_newton_dr500_vision_h32_b32_20k_20260929

예상되는 동작#

이 model은 simulation의 state-machine demonstration 500개로 학습했습니다. Placement 후 복귀 동작이 data에 없으므로 반복보다 정지하는 동작을 예상하세요. 기본 시작 pose에서의 동작을 다음 실행의 dataset-derived start와 비교합니다.

직접 수집한 teleoperation model은 your_hf_username/so101_teleop_vials_newton_GR00T17, 자동 수집 예시는 your_hf_username/so101_auto_vials_newton_GR00T17을 사용합니다. Local checkpoint는 models/ 또는 outputs/train/ 아래에서 선택한 pretrained_model directory의 container 절대 경로로 MODEL_ID를 설정하세요. Background server는 같은 filesystem과 mount를 읽습니다. Download a Compatible Policy를 참고하세요.

  1. 두 camera와 기본 시작 pose로 episode 10개를 실행합니다.

중요

첫 실행에서는 낮은 성공률을 예상합니다. 일부러 distribution 밖의 pose에서 시작하는 비교이므로, 선택한 policy가 기본 pose에서 어려움을 겪을 것으로 예상됩니다.

lerobot_eval --task Newton-So101-Teleop-Vials-To-Rack-DR-Eval-v0 --cameras all --browser-display presets=newton,ovrtx_renderer --server_address localhost:8080 --pretrained_name_or_path "$MODEL_ID" --policy_type groot --policy_device cuda --action_horizon 16 --num_episodes 10 --seed 76000 --lang_instruction "Pick up the vial and place it in the rack"

  1. http://localhost:8090을 열어 camera feed와 telemetry를 확인합니다. Page에 focus를 두고 R을 누르면 현재 episode를 중단하고 scene을 reset합니다. Viewer에는 tab 하나만 연결하세요.

  2. 평가가 실행 중이면 Ctrl+C로 끝내고, 같은 shell에서 policy server도 종료합니다.

kill "$POLICY_SERVER_PID"
wait "$POLICY_SERVER_PID" || true
unset POLICY_SERVER_PID

또는 container의 모든 policy server를 종료합니다.

pkill -f '[l]erobot\.async_inference\.policy_server'

Dataset-Derived Starting Pose 비교#

  1. Policy server를 재시작하고 Policy server ready를 기다립니다.

python -m lerobot.async_inference.policy_server --host=0.0.0.0 --port=8080 --fps=30 --inference_latency=0 > outputs/policy-server.log 2>&1 & POLICY_SERVER_PID=$!
python -c "import grpc; grpc.channel_ready_future(grpc.insecure_channel('localhost:8080')).result(timeout=60); print('Policy server ready')"

  1. 같은 평가에 --start_pose_dataset을 추가해 실행합니다. Model, task, seed, episode 수는 유지하세요.

lerobot_eval --task Newton-So101-Teleop-Vials-To-Rack-DR-Eval-v0 --cameras all --browser-display presets=newton,ovrtx_renderer --server_address localhost:8080 --pretrained_name_or_path "$MODEL_ID" --policy_type groot --policy_device cuda --start_pose_dataset sreetz-nv/so101_newton_dr500_20260923 --action_horizon 16 --num_episodes 10 --seed 76000 --lang_instruction "Pick up the vial and place it in the rack"

이 flag는 지정한 dataset의 episode 시작 joint position 평균을 사용하며 gripper opening도 포함합니다. Terminal의 [Start pose]에서 dataset 이름, 평균, 표준편차를 확인하세요. 매번 기록된 시작 pose를 sampling하는 방식이 아니며, 평균 하나만으로 모든 checkpoint의 시작 조건을 포괄한다고 보장할 수 없습니다.

  1. 두 실행을 비교하세요. 이 예시에서는 dataset-derived start에서 성공률이 크게 높아질 것으로 예상합니다. Grasp 접근이 나아졌나요? Policy weight는 같은데 무엇이 달라졌나요?

Release 이후에는 어떻게 될까?#

Vial을 놓은 뒤 policy가 home으로 복귀하지 않습니다. 이유를 생각해 보세요.

Robot이 Home으로 복귀하지 않는 이유

이 model의 state-machine demonstration은 home으로 돌아오지 않고 끝나서 해당 동작을 배우지 못했습니다. 반복 가능한 loop를 가르치려면 release 후 ready pose로 복귀하는 motion도 demonstration에 포함하고 학습·평가해야 합니다. 다음 model에서 이를 살펴봅니다.

Evaluation reset은 학습된 복귀 동작과 별개입니다. Policy가 home 복귀를 배우지 않았더라도 simulator는 placement 후 reset할 수 있습니다.

Display 없이 평가#

Display 없는 평가 명령 보기

Dataset-derived-start 평가를 display 없이 반복하려면 --browser-display를 빼고 실행합니다. Camera와 두 preset은 여전히 필요합니다.

lerobot_eval --task Newton-So101-Teleop-Vials-To-Rack-DR-Eval-v0 --cameras all presets=newton,ovrtx_renderer --server_address localhost:8080 --pretrained_name_or_path "$MODEL_ID" --policy_type groot --policy_device cuda --start_pose_dataset sreetz-nv/so101_newton_dr500_20260923 --action_horizon 16 --num_episodes 10 --seed 76000 --lang_instruction "Pick up the vial and place it in the rack"
Camera 호환성 확인

현재 observation은 wrist와 external을 사용하며, LeRobot의 observation.images.wrist와 observation.images.external에 대응합니다. 이 이름으로 학습한 checkpoint에는 rename map이 필요하지 않습니다.

Camera feature가 ego와 external_D455인 호환 가능한 이전 LeRobot checkpoint에는 --rename_map '{"wrist":"ego","external":"external_D455"}'를 추가합니다. 방향은 simulation camera name → checkpoint feature name입니다. 적용 전에 checkpoint를 확인하세요. Key 이름 변경으로 camera pose, optics, joint 규약, model format 차이까지 해결되지는 않습니다.

  1. 평가 client를 Ctrl+C로 종료하되 server는 계속 실행합니다.

  2. 같은 checkpoint를 DR evaluation task에서 실행합니다.

lerobot_eval --task Newton-So101-Teleop-Vials-To-Rack-DR-Eval-v0 --cameras all --browser-display presets=newton,ovrtx_renderer --server_address localhost:8080 --pretrained_name_or_path "$MODEL_ID" --policy_type groot --policy_device cuda --start_pose_dataset sreetz-nv/so101_newton_dr500_20260923 --action_horizon 16 --num_episodes 10 --seed 76000 --lang_instruction "Pick up the vial and place it in the rack"

Camera 비교와 Domain Randomization 설정 범위를 확인하세요. Checkpoint 비교에는 같은 episode 수와 seed(--seed)를 사용합니다.

결과 관찰과 기록#

  • Terminal에 진행 상황과 grasp/placement event가 표시됩니다.

  • Evaluation task는 placement, timeout, unsafe rack state에서 reset됩니다.

  • Timeout 없이 task 성공 조건을 만족한 경우에만 성공으로 계산합니다.

  • Safety reset 자체는 성공이 아닙니다.

  • Summary와 함께 rollout도 관찰해 실패 양상을 이해하세요.

  1. Model, task ID, seed, episode 수, action horizon, placement 성공 수, 실패 양상을 기록합니다. Grasp 누락, 낙하, rack 충돌, 조명 민감도를 살펴보세요.

다른 environment도 시험하세요: 같은 seed, episode 수, action horizon으로 기본 또는 DR environment에서 실행합니다. 결과가 어떻게 달라지나요? Training data 수집 환경과의 조명, material, camera view, object 배치 차이가 policy의 입력과 동작에 미치는 영향을 생각해 보세요.

Workshop의 control 및 camera cadence는 30 Hz입니다. GPU 경합과 inference latency가 실제 rollout 속도에 영향을 줄 수 있습니다.

평가 종료#

  1. Ctrl+C를 눌러 실행 중인 평가를 끝내고 prompt를 기다립니다. 모든 episode가 끝났다면 이미 prompt로 돌아와 있습니다.

  2. 같은 shell에서 background server를 종료해 GPU memory를 해제합니다. Policy 평가를 마칠 때마다 다음 policy를 평가하기 전에 이 명령을 실행하세요.

kill "$POLICY_SERVER_PID"
wait "$POLICY_SERVER_PID" || true
unset POLICY_SERVER_PID

또는 container의 모든 policy server를 종료합니다.

pkill -f '[l]erobot\.async_inference\.policy_server'

  1. 다음 simulation 평가를 위해 이 terminal과 workshop container는 열어 둡니다.
